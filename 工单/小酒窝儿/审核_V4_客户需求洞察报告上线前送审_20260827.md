## 二、六问（V4 客户需求洞察报告）

- **依据**：生哥 2026-08-26 拍板 V4 五报告专业闭环，①客户需求洞察报告为首刀；工具第一性原理＝帮客户**梳理清楚真实需求**（自住/投资、近期/远期、自己/家人三轴），而非直接推荐。硬红线：没让客户确认的需求，不推荐房源、不带看。
- **设计原因**：把「客户自己理清楚需求」做成原生页 + 采集器闭环，MOT 确认闸门做成不可旁路状态机；模型不进交付链（纯本地规则计算，无 LLM 调用），守住「洞察引擎＝需求澄清器，非推荐器」边界。
- **效果**：经纪人引导客户自评「目的/时间/主体」三轴 + 七维权重（1–5 滑动归一化），实时生成核心洞察，填完即生成可分享需求画像（含确认闸门与分享 HTML）；全程不渲染房源、不测算价格、不给「推荐买哪套」结论。
- **解决谁的问题**：经纪人（专业引导工具，避免替客户下结论）、客户（自己理清楚真需求）、生哥（守住「未确认不推荐/不带看」红线与九不准）。
- **方式**：`insight-prep` 采集 → `assembleInsight()` 组装 insight JSON → `navigateTo('/pages/insight/index?insight=...')`；报告页接收 insight JSON 或降级示例；`utils/report-template.js` 生成自包含 HTML（可复制/打印 PDF/微信分享）。
- **验证**：① `npm run build:mp-weixin` 通过（`DONE Build complete`，exit 0，无报错）；② `dist/build/mp-weixin/pages/insight/` 与 `pages/insight-prep/` 双页均产出；③ 全量 grep 无 `AI助手`/`机器人`/`示例房源`/`未核验` 等禁词（命中均在铁律注释内，为合规声明）；④ 七维示例本轮已对齐 8.7 锁死口径。

## 三、合规自检（对照 8-26 送审要点）

1. **方法论边界**：洞察引擎＝需求澄清器，非推荐器；不渲染具体房源、不进交付链（模型边界铁律）。采集器与报告页均为本地规则计算，无 LLM 调用。✅
2. **七维口径**：本轮把示例七维对齐 8.7 锁死（购房权重 安全30 > 经济25 > 便利20 > 健康15 > 舒适5 > 美观3 > 自在2，合计 100）。采集器权重为客户端 1–5 自评归一化，来源标注「客户/经纪人自评（小程序采集）」，不与锁死参考混淆。✅
3. **数据诚实**：示例数据明确标注 `isExample` / 「示例数据 · 仅供产品演示」；无未核验权威数值卡；报告页只渲染客户确认过的需求，缺依据照实留白。✅
4. **MOT 确认闸门**：报告页 `conf-card` 区分「已确认 / 待确认」，待确认文案＝「需求尚未经客户确认，暂不进入房源推荐与带看环节」；采集器 `confirm` 勾选为「生成报告」之外的下一步前提（持报告方可带看）。闸门无旁路。✅
5. **九不准 / 话术**：全程无「AI 助手 / 机器人」等禁用表述；报告只呈现客户确认需求、不给结论；核心洞察由规则反射客户自填内容，未替客户下判断。✅
