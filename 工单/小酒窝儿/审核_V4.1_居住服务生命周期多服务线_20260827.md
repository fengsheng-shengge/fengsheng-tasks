## 一、本次改动说明

设计方向来自生哥 2026-08-27：「整体按照服务客户的角度，接触到成交售后，后面有新的居住服务再循环的逻辑设计，把租赁、买卖都放进去，后面还可以补充家装、资产管理、出售变现、置换、出租托管等」。

V4.0 的「单条买卖五报告闭环」升级为 **「以服务客户为轴的可循环生命周期」**：

- 生命周期五步：`接触 → 方案 → 行动 → 成交 → 售后`，售后完成后可开启新一轮服务，循环回新服务线。
- 服务线（每线一套五步闭环，报告带 `serviceLine` 标记）：
  `buy 购房 / sell 售房 / rent 租住 / host 出租托管 / decor 家装 / asset 资产管理 / replace 置换`。
- 同一客户可同时拥有多条服务线；客户驾驶舱支持服务线切换，生命周期进度 / 报告清单 / 待办跟随当前线。
- 老数据兼容：历史报告无 `serviceLine` 标记时，按客户档案 `typeKey / stage / rel` 兜底推断服务线。
- 数据诚实：生命周期状态全部由 `client.reports[] + serviceLine` 派生，不持久化冗余状态；报告落库 append-only，保留版本痕，确认记录只新增不改写。
- 闸门 1（需求确认）照常生效；闸门 2/3 在 ②-⑤ 样本未审核前保持「待样本」锁定态，不渲染空壳能力。

## 三、六问（V4.1 居住服务生命周期）

- **依据**：生哥 2026-08-27 迭代方向「以服务客户为轴，接触到成交到售后，售后后有新的居住服务再循环」；V4.0 已确认五报告闭环与三道硬闸门。
- **设计原因**：单条买卖闭环把「客户」切成了多张孤立卡片；生命周期把客户当作长期服务对象，一次成交只是中途节点，售后沉淀信任后自然引出下一轮服务（售房 / 置换 / 家装 / 资产管理 / 出租托管）。
- **效果**：经纪人面对老客户时能看到完整服务史，按服务线推进当前轮次；客户成交 + 售后后可一键开启新一轮服务，同一档案沉淀多条服务线。
- **解决谁的问题**：经纪人（老客户持续服务、避免丢单）、客户（一以贯之的居住服务体验）、生哥（「一次委托 · 终生服务」落地、售后飞轮转信任与转介绍）。
- **方式**：报告按 `serviceLine` 标记；`deriveServiceLines` 从 `client.reports[] + serviceLine` 派生所有服务线；`deriveLifecycleState(client, targetLine)` 派生当前线五步状态；驾驶舱切换服务线即切换生命周期进度/报告/待办；完成态弹层选新线后进入问诊页。
- **验证**：① `npm run build:mp-weixin` 通过（`DONE Build complete`，exit 0）；② 首页 / 客户列表 / 驾驶舱 / 问诊页 / 档案页服务线语义一致；③ 全量 grep 无 `AI助手` / `机器人` 等禁词；④ 闸门 2/3 保持「待样本」锁定，不渲染空壳能力。
