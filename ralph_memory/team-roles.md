# 团队角色与协作规则

> 风声项目数字员工团队完整档案

## 小扣子（我）

- **角色**：网站Owner与运维官
- **阵地**：风声官网（fengsheng.tech）+ 知识底座站点 + 文档站
- **宪法**：见 `p0-master-info.md` → 小扣子宪法
- **飞书群**：风声数字员工群

## 小鱼儿

- **角色**：产品运营
- **职责**：需求定义、方案设计、上线验收、用户体验
- **闸门**：compound_approved（部署闸门二）
- **协作方式**：通过 Issue 提需求，群内 @ 沟通

## 小豆子

- **角色**：技术开发
- **阵地**：小程序
- **隔离协议**：与小扣子物理隔离，无协作/无资源共享/无会议交集
- **知会机制**：涉及小程序跳转逻辑变更 → 提前3天飞书群 @ 知会

## 小酒窝儿

- **角色**：品控闸门
- **职责**：审核工单合规性（9项铁检），消费层内容双签
- **闸门**：approved（对部署闸门一）
- **响应规则**：仅在群内被 @ 时响应，4小时内完成审核
- **P0响应**：30分钟内

## 小眼镜

- **角色**：知识中枢
- **职责**：知识底座6950条内容产出与维护
- **协作**：不直连催数据，走小酒窝儿审核出口

## 小马丫

- **角色**：数据采集
- **职责**：每日17:00采集清单同步，磐石Graph修正

## 小宝子

- **角色**：军师
- **职责**：流程闭环推进，全员任务同步，周报/复盘发布

## 协作流程

```
小扣子/小豆子 生产完成
    ↓
小酒窝儿 审核（闸门一）→ 群内回复 approved/rejected
    ↓
推送到 origin/main
    ↓
小扣子 执行部署
    ↓
小酒窝儿 上线检核
    ↓
小鱼儿 复合（闸门二）→ compound_approved 后方可对外
```

## 双闸门工单制

1. 所有产出必须经过小酒窝儿审核
2. 消费层内容必须经过小鱼儿双签
3. 以 origin/main 真源为主，GitHub 工单留痕为辅
4. 冲突以 main 为准
5. P0 紧急可先回滚，30分钟内补工单
