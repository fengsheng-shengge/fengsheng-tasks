1.2 待修清单（5 项）

B1 · 路由冲突：内部考核页 URL 被改写成公开测评页 必修 · P0

_redirects 第 17-18 行仍然写着：

/assessment /assessment/ 200
/agent-assessment /assessment/ 200
/agent-assessment/ /assessment/ 200

后果：内部「数字员工五把尺子考核」已迁到 /agent-assessment/，但这两条 200 改写会把该 URL 的请求映射到 /assessment/——而 /assessment/ 现在是公开的「数智新居住顾问能力测评」。等于首页管理者入口的「五把尺子考核」点进去看到的是公开测评页，内部页打不开。

修复：删除这两行，交回 Cloudflare Pages 目录式路由（自动命中 agent-assessment/index.html）。

B2 · 重定向规则双份维护，且有一条语义错指 修 · P0

同一条重定向在 _worker.js（legacyPageRedirects，第 3449-3459 行）和 _redirects 里各写了一遍，且两边内容不一致：worker 有 /terms.html、/agreement/，_redirects 没有；_redirects 有 /dashboard、/assessment 等 200 改写，worker 没有。

更大的问题是 /assessment.html 的指向：

_worker.js:3455  '/assessment.html': '/quality-test/',   // 指到「六维品质测评」，语义错
_redirects:33     /assessment.html /quality-test/ 301      // 同一处错误

修复：收敛为单一事实源（建议保留 _worker.js，它是代码可控、可测试的）；/assessment.html 改指 /assessment/（公开能力测评才是 assessment 的正主）。

B3 · 命名冲突：5 个"测评"互相指串 必修 · P0

路径页面真名（取自页 title）被别处叫什么冲突
/care-test/服务者四维 · 关怀测评首页工具箱标签：「品质测评」重名
/quality-test/风声 · 六维品质测评该页页脚导航：「品质测评」与上面撞名
/assessment/数智新居住顾问能力测评首页/知识库：「能力测评」—
/knowledge/quiz/风声 · 掌握度测评——
/agent-assessment/数字员工考核统计 · 五把尺子首页：「五把尺子考核 🔒」内部页，命名清楚

修复：确立一条命名规则——「品质测评」专属 /quality-test/；「关怀测评」专属 /care-test/。首页经纪人工具箱里 /care-test/ 的标签由「品质测评」改为「关怀测评」；新用户引导第 1 步「完成品质测评」同步改为「完成关怀测评」。两页页脚导航对齐。

B4 · 别名重写指错 修 · P0

_redirects 第 3-4 行：

/dict/* /knowledge/ 200      // 词典别名 → 知识库，但 /dictionary/ 独立存在
/decode/* /care-test/ 200    // 解码器别名 → 关怀测评，语义完全不符

修复：改为 /dict/* → /dictionary/、/decode/* → /decoder/。

第二部分 · P0-02 首页信息架构重构

2.1 现状复核：现版结构被 PRD 描述低估了

实测 index.html，现版已经不是"12 个工具等大平铺"。真实结构是：

导航(fs-nav 注入)
role-guide   —— 一句话价值
role-switcher —— 三 Tab：我是经纪人 / 我是管理者 / 我是新用户
hero          —— 品牌 + 主标题
stats-section —— 4 个规模数字（口径已在上一轮改为"目标版"）
role-content ×3 —— 每个角色内容不同
  · 经纪人：5 张 scene-card + 三组工具箱（服务客户/专业提升/效率工具，共 12 项）
  · 管理者：6 张 scene-card + 三组工具箱 + 方法论库 3 项
  · 新用户：3 步新手引导 + 推荐了解 4 项
daily-section —— 今日知识
真正的问题不是"没有角色",而是"没有层级"：同一个角色下，5-6 张 scene-card 与 12 项工具卡片尺寸权重几乎相同，用户仍要自己判断"先点哪个"。P0-02 要解决的是黄金焦点缺失，不是推翻现有 Tab。

2.2 目标结构：每个角色内容区从"等权列表"改为三层

L1
黄金主任务卡（1 张）
深绿渐变 #3d5a3e → #2c4430，白字，全宽，视觉权重最高。回答"我现在最该做的一件事"。
L2
次任务卡（2 张并排）
白底 + 1px 边框，grid-template-columns:1fr 1fr（≤720px 降为单列）。回答"顺手的第二、第三件事"。
L3
全部工具（可折叠，默认收起）
用 <details>，summary 文案「▸ 全部工具（按任务分组）」。展开后即现有的工具箱分组，一项不少。

2.5 改动范围（克制，避免连带风险）

只动 role-content 内部结构，不动其余区块。具体：hero、stats-section、daily-section、导航、switchRole 逻辑、tracker.js、chat-fab 均保持原样。这样可以把改动面收敛到"每个角色的内容区"，回滚成本最低。

2.6 验收标准

  • 首屏（滚动前）唯一的"最大视觉元素"是 L1 主任务卡（面积大于任意其他卡片）
  • 三 Tab 的 L1 标题互不相同（策展 / 智能体学院 / 3 步引导）
  • 「全部工具」默认收起；展开后仍能触达现版全部工具项，无丢失（经纪人 12 项、管理者 12 项 + 方法论 3 项）
  • ≤720px 时 L2 变单列，全页无横向溢出
  • 旧用户高频入口（策展、知识库、AI 对话）点击层级 ≤ 2 次（Tab + 1 次点击）
