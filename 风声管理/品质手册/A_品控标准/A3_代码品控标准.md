# A3 代码品控标准

> 版本：v1.0 | 日期：2026.6.23 | 来源：白皮书v1.0+安全审计报告提炼
> 适用范围：所有fengsheng.tech前端代码变更

---

## 一、编码铁律

| # | 规则 | 原因 |
|---|------|------|
| 1 | 禁止sed修改含JS模板字符串的HTML | sed无法区分HTML标签和JS模板字符串中的标签 |
| 2 | 批量修改统一用Python脚本 | 可控、可追溯、不会注入失败 |
| 3 | 禁止innerHTML拼接用户输入 | XSS风险 |
| 4 | SVG必须消毒后再渲染 | innerHTML拼接SVG是"定时炸弹" |
| 5 | URL参数必须编码 | 防注入 |
| 6 | 经纪人表单输入必须校验 | 手机号格式+字符串长度+XSS过滤 |

## 二、代码结构规范

| 规范 | 要求 |
|------|------|
| 共享组件同步 | 改导航/CSS/版权→全站9页面同步 |
| 增量迭代 | 禁止覆盖式替换，版本可溯源 |
| 全量部署 | 每次部署必须包含全站所有文件 |
| 路径确认 | 改前确认线上实际路径，不盲猜 |
| 依赖检查 | 改任何共享组件前查依赖地图 |

## 三、变更检查

改代码前必答：
1. 改什么文件？改什么内容？
2. 谁依赖它？（查依赖地图）
3. 必须同步改什么？
4. 有没有JS模板字符串？
5. 有没有同名文件混淆？
6. 回滚方案是什么？

## 四、禁止操作

| 🚫 禁止 | 原因 | 正确做法 |
|---------|------|---------|
| sed改含JS的HTML | 上次注入失败元凶 | Python脚本 |
| 增量部署（只传部分文件） | 缺文件=404 | 全量部署 |
| 用线上curl下载的文件覆盖部署 | 源码不可靠 | 从本地备份/仓库恢复 |
| 手动逐文件修改 | 漏改概率极高 | Python批量脚本 |
| 跳过检查清单直接部署 | 9次事故归因 | 逐项打勾 |
