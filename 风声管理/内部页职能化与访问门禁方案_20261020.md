## 3. 第二步：访问门禁

### 3.1 方案 A（推荐）：Worker 层签名 Cookie 门禁

**复用现有能力**：`env.JWT_SECRET`（HS256 签名，`generateToken`/`verifyToken` 已就绪）、`env.DASHBOARD_TOKEN`（现用于 `/api/admin/agents` 的 Bearer 口令校验）。

**新增**：
1. `POST /api/internal-gate`：校验请求口令（复用 `DASHBOARD_TOKEN`，或新增 `env.INTERNAL_GATE_TOKEN`）→ 签发 12h JWT → 下发 `Set-Cookie: fs_internal=<jwt>; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=43200`。
2. `/gate` 静态页：口令输入页，带 `?next=` 回跳参数。

**Worker 拦截点**：在 [`_worker.js`](../_worker.js) 的 `env.ASSETS.fetch(request)` 之前，对受保护路径先验 Cookie，无效则 `302 → /gate?next=<path>`：

```
/dashboard          /dashboard/
/agent-assessment   /agent-assessment/
/management         /management/
```

> 执行校准（2026-10-20 落地）：`/dashboard-manager/` 经复核为面向门店管理者的**公开产品 demo**（内容为通用示例智能体，零内部角色名、零敏感数据，首页以「我的团队总览」公开展示且无内部标识），故**不纳入门禁、不加 noindex、robots 不屏蔽**，保留公开产品漏斗。原 `/assessment/` 为公开能力测评页，未纳入门禁；内部考核页已独立到 `/agent-assessment/`。

**优点**：零外部依赖、零成本、可复用现有密钥、删拦截即回滚。
**缺点**：口令为共享密钥（非个人账号），需定期轮换；无法区分「谁看过」。

### 3.2 方案 B（可选升级）：Cloudflare Access（Zero Trust）

在 CF 控制台对受保护路径配置 Access 应用策略（邮箱 OTP / SSO）。

**优点**：有个人身份、有审计日志。
**缺点**：需 CF 控制台配置、可能涉及付费席位、国内访问的验证体验受限。

### 3.3 方案 C（不采用）：纯前端口令

明文写在前端、禁用 JS 或改代码即可绕过，仅「防君子」。**不作为正式门禁**，仅可作方案 A 的过渡壳。

> 建议：**A 先行上线**，B 作为后续可选加固。

## 4. 第三步：搜索引擎收口

1. `robots.txt` 补：`Disallow: /agent-assessment/`（`/dashboard/`、`/management/` 原已屏蔽）。
2. `sitemap.xml` 删除 `/dashboard/` 条目（内部页不应出现在 sitemap；`/assessment/` 为公开页，保留）。
3. 三个内部页（`/dashboard/`、`/agent-assessment/`、`/management/`）`<head>` 加 `<meta name="robots" content="noindex,nofollow">`。
4. 公开页 `/assessment/`、`/dashboard-manager/` 不屏蔽、不 noindex。

---

## 5. 第四步：首页入口处理

- 保留 3 个入口（已定）；
- 入口标签加「内部」标识（如 🔒），避免访客误当成公开功能；
- 未登录点击 → 落 `/gate`，通过后正常进入。

## 6. 实施顺序与验收标准

| 步骤 | 改动文件 | 验收点 |
|---|---|---|
| 1. 文案职能化 | `dashboard/`、`assessment/`、`management/` 三页 | 三页访客可见文案零角色名；职能称呼映射一致 |
| 2. 搜索收口 | `robots.txt`、`sitemap.xml`、三页 head | `curl` robots 含三条新 Disallow；sitemap 不再含 `/assessment/`、`/dashboard/`；页面含 noindex |
| 3. 门禁 | `_worker.js`、新增 `/gate`、`/api/internal-gate` | 未带 Cookie 访问受保护路径 → 302 `/gate`；带有效 Cookie → 200；口令错误 → 401 |
| 4. 首页入口 | `index.html` | 3 入口带「内部」标识；点击未登录落 `/gate` |

## 7. 风险与待办

- **口令分发**：门禁上线后，内部同事需知道口令获取途径，否则会被自己挡在门外。需指定口令保管与通知方式。
- **`/assessment/` 语义错配待决**：`/okr.html`、`/standard/`、`/skills/` 把它当「免费测评 / 免费使用」公开引流，而它实际是内部考核页。建议把这几处 CTA 改指向 `/quality-test/`（公开品质测评）。**需单独拍板**。
- **缓存**：Cloudflare 边缘可能缓存旧 HTML，改动上线后需 purge 对应路径。
- **后续生成脚本**：若日后由脚本自动生成看板，需同步脚本模板，否则角色名会回流。
