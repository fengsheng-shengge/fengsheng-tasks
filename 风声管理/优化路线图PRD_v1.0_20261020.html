风声网站优化路线图 PRD

版本 v1.0 · 2026-10-20 · 基于全站40页面盘点 + 架构师/资本双视角分析

一、项目概述

背景：风声·居住决策底座当前已具备扎实的知识底座（5843词条/76场景/13知识域）和成熟的视觉设计质感，但存在"信息架构平铺化、转化路径断裂、知识与工具两张皮"三大结构性问题。

目标：用三个阶段的迭代，把站点从"工具罗列型知识库"升级为"任务驱动型、有信任证据、能产生付费闭环的专业服务平台"。

范围：首页重构、清理占位页、信任资产建设、转化路径打通、用户体系、知识→决策闭环。

二、P0 · 止血项（1-3天）

目标：消除用户踩空页面的体验裂痕，把首页从"工具超市"改成"任务导航"。这阶段不做新功能，只做结构修复——但对信任的影响立竿见影。
P0-01 清理"建设中"占位页与重复页面
P0 预估：0.5天

问题（2026-10-20 全站实测复核）：此前盘点的 about/terms/privacy 占位页、根级 .html 重复页、s1-report 无 title 均已完成收敛，不再是问题。当前真实待修的是路由冲突：_redirects 仍把 /agent-assessment 200 改写到 /assessment/，导致内部「五把尺子考核」URL 实际显示公开能力测评页；另有 _worker.js 与 _redirects 双份重定向规则（其中 /assessment.html → /quality-test/ 语义错指），以及 5 个"测评"页命名互串、/decode/* 与 /dict/* 别名重写指错。详见《P0-01+P0-02 细化设计》。

动作：

① 修路由冲突：删除 _redirects 中 /agent-assessment → /assessment/ 两条 200 改写，交回目录式路由；
② 重定向收敛为单一事实源，/assessment.html 改指 /assessment/；
③ 统一"测评"命名（/care-test/ 一律称"关怀测评"，"品质测评"专属 /quality-test/）；
④ 修正别名重写 /decode/* → /decoder/、/dict/* → /dictionary/；
⑤ 清理卡片级占位：三处"居住服务业务字典·即将上线"统一成一个口径。

✅ 验收标准
  • curl -I /agent-assessment/ 返回内部「五把尺子考核」页，不再是公开能力测评页
  • curl -I /assessment.html 返回 301 → /assessment/
  • 全站正文 grep「建设中」为 0；「即将上线」仅出现在明确的对外路线图处且带说明
  • 首页「关怀测评」标签与 /care-test/ 页标题一致，"品质测评"不再同时指两个页面
  • /decode/*、/dict/* 别名与实际页面同源
P0-02 首页信息架构重构：从工具宫格→任务路径
P0 预估：2天

问题（2026-10-20 实测复核）：首页已具备角色 Tab 与按任务分组的工具区，三 Tab 内容确实不同；真正的问题是层级缺失——每个角色 5-6 张场景卡 + 12 项工具卡片尺寸权重几乎相同，没有黄金焦点，用户仍需自己判断"先点哪个"。

动作：按配套的《首页改版原型v1》实施——

① 首屏只放1个最高频主任务大卡（接到客户→策展引擎），用绿色边框+大尺寸；
② 下方并排2个次任务卡（提升专业→知识库 / 回复客户→AI对话）；
③ 完整工具区收到底部，改为次要视觉层级（默认折叠）；
④ 三个角色Tab切换后，主/次任务卡同步替换（沿用现有 switchRole，本次只改层级、不改内容来源）。

✅ 验收标准
  • 首屏（滚动前）视线落点在主任务大卡上，不再是12个等大宫格
  • 经纪人/管理者/新用户三个Tab切换后，主标题、主任务卡完全不同
  • 完整工具列表仍可从首页找到，但视觉权重明显降低
P0-03 首屏视觉层级拉开：数据区换血
P0 预估：0.5天

问题：现有数据区"5843词条/76场景/13知识域/6数字员工"全是自证规模数字，用户感知不到"这对我有什么用"。

动作：把数据区拆成"真实现状 + 明确目标"两层，不编造结果数据：

① 真实现状（可核对）：保留知识底座的真实存量——5,843 条专业词条 · 76 个业务场景 · 13 个知识域 · 6 个数字员工，标注来源与更新日期（来源：风声知识底座 v2.3，更新于 2026-10-15）；
② 结果目标（明确标注为"目标"）：累计生成客户报告（上线 12 个月目标 1,000+ 份）· 服务居住服务者（目标 500+ 位）· 方案采纳率（目标 ≥80%）· 使用满意度（目标 ≥4.8 分）；
③ 23 年行业方法论沉淀（创始人背书，真实可核对）；
④ 补一句"目标达成后同步更新"，避免把目标误读为实绩。

✅ 验收标准
  • 数据区至少2项是"结果类指标"（不是规模类），且全部标注为"目标"并写明目标周期
  • 真实存量数字（词条/场景/知识域）保留，标注口径来源与更新日期，避免"自说自话"
  • 无真实结果数据时不得编造：不得用虚构数字冒充实绩，结果类一律以"目标"呈现

三、P1 · 信任与转化层（1-2周）

目标：让用户从"觉得不错"走到"愿意试→愿意留→愿意付费"。这阶段是商业闭环的起步，也是资本看"能不能独立存活"的关键证据。
P1-01 首页新增"信任证据区"
P1 预估：2天

问题：一个给居住服务者的专业平台，首页没有任何"凭什么信你"的第三方证据。

动作：在首页数据区下方，新增一个横向滚动的证据区：

① 2-3条真实服务者证言（姓名/城市/从业年限 + 一句话评价）
② 1-2个成功案例摘要（用了风声后，效率提升X% / 成交周期缩短X天）
③ 创始人背书区（23年行业经历，照片+一句话定位）
④ 如有行业合作/媒体报道，放logo墙

✅ 验收标准
  • 首页至少出现2条带姓名和城市的真实用户证言
  • 有1个可量化的"用了之后怎么样"的案例
  • 创始人背书区不超过3行字，有照片（或专业头像）
P1-02 打通 partner→purchase→survey 转化路径
P1 预估：3天

问题：合作页、咨询页、调研页已存在，但首页和知识库页没有任何转化引导。0→1的商业闭环在页面层是断的。

动作：

① 在知识库页面底部，埋一个"深度咨询/定制化方案"的CTA卡片
② 策展引擎生成完报告后，引导"预约1对1解读"（purchase页）
③ 新用户3分钟体验结束后，引导"填写调研问卷，获取完整报告"（survey页）
④ 每个转化入口都有明确的"用户能得到什么"，不是干巴巴的"联系我们"

✅ 验收标准
  • 知识库页底部有转化CTA，点击率可统计
  • 策展引擎结果页有下一步引导（不是看完就走）
  • 三个转化页（partner/purchase/survey）的内容不是"建设中"，有实质信息
P1-03 轻量用户体系：登录 + 收藏/历史云端同步
P1 预估：4天

问题：目前收藏/历史/测评结果都存在浏览器本地，换设备就丢。这对工具型产品是硬伤——用户数据是留存的根基，也是未来免费/付费分层的前提。

动作：

① 接入微信扫码登录（最轻量，B端用户无感知）
② 收藏的词条、历史生成的报告、测评结果，全部云端保存
③ 登录后，首页根据用户使用历史，推荐"你常用的3个工具"
④ 暂不做付费墙，先把用户体系建起来

✅ 验收标准
  • 微信扫码可登录，登录后收藏/历史在另一台设备上能看到
  • 未登录状态下，核心功能（查词条、生成报告）仍可用，但结果不保存
  • 有简单的用户中心页面（查看历史、管理收藏）
P1-04 SEO title 与 meta description 重写
P1 预估：1天

问题：当前title是"风声·居住决策底座 | 通过独立价值赢得尊严"——这是品牌slogan，不是用户搜索词。经纪人不会搜"居住决策底座"，他们搜"二手房话术""买房注意事项""房产知识"。

动作：

① 首页title改为："房产经纪人知识库_专业话术与客户服务工具 - 风声"
② 每个功能页的title，用用户搜索词命名（如"二手房客户跟进话术_买房全周期报告生成 - 风声"）
③ 每页补meta description，包含核心关键词

✅ 验收标准
  • 首页title包含至少1个用户高频搜索词
  • 抽查5个核心功能页，title不是品牌slogan，而是功能描述
  • Google/百度站长平台可收录（提交sitemap）

四、P2 · 知识→决策闭环（1-3月）

目标：从"内容平台"升维到"能力工具"。这是资本真正愿意买单的那一步——不是5843条词条，而是"输入客户信息→输出可直接用的方案"的生成闭环。
P2-01 策展引擎打穿 L2：从"客户信息"到"全周期报告"
P2 预估：2周

问题：策展引擎已有雏形，但和知识库是"两张皮"——没有调用5843条词条的知识积累，生成质量受限。

动作：

① 策展引擎的生成逻辑，接入知识库检索（RAG）——不是套模板，而是基于真实行业知识生成
② 报告结构标准化：客户画像 → 需求分析 → 匹配建议 → 跟进策略 → 话术建议
③ 生成完报告后，每个段落都标注"参考了哪个知识域/词条"（可溯源，增强信任）
④ 经纪人可以对报告打分（采纳/不采纳），数据反哺优化生成质量

✅ 验收标准
  • 输入客户基本信息（预算/区域/需求），30秒内生成一份结构完整的全周期报告
  • 报告不是通用模板，能根据不同客户类型（首套/改善/投资）差异化生成
  • 报告每章可溯源到知识库的具体内容
  • 有"采纳率"统计，采纳率作为产品优化的核心指标
P2-02 数字员工从"静态展示"到"真跑起来"（L3）
P2 预估：1月

问题：6个数字员工目前只是列出来，没有实际跑业务。资本真正买单的是L3——持续跟进客户的陪伴式数字员工，而不是L1的一次性查询工具。

动作：

① 先选1个数字员工做MVP："话术员Agent"——客户在微信/IM里问了问题，Agent自动基于知识库生成专业回复建议，经纪人一键发送
② 再做"策展员Agent"——客户档案更新后，自动生成跟进建议/阶段报告
③ 管理者后台能看到每个数字员工的运行数据（处理了多少任务、采纳率多少）
④ 这是订阅制付费的核心钩子——"数字员工替你干活"比"知识库查询"值钱10倍

✅ 验收标准
  • 至少1个数字员工能端到端跑通（从接收任务→生成结果→经纪人采纳）
  • 管理者后台能看到数字员工的运行数据看板
  • 有明确的"免费额度/付费升级"边界（如：每月免费生成3份报告，超出付费）
P2-03 数据飞轮：用户画像→精准推荐→越用越懂你
P2 预估：1月

问题：没有用户体系，就没有"越用越懂你"，资本最看重的复购/留存逻辑就不存在。

动作：

① 基于用户的使用行为（常查的词条、常生成的报告类型、常服务的客户类型），建立用户画像
② 首页个性化推荐："你常遇到投资型客户，推荐你看这3个场景的话术"
③ 生成的报告/回复，根据用户历史偏好自动调整风格（如：有的经纪人喜欢简洁，有的喜欢详细）
④ 这是"留存护城河"——用得越久，迁移成本越高

✅ 验收标准
  • 登录用户的首页，推荐内容与未登录用户不同（基于行为数据）
  • 有"你的常用工具/最近使用"区域，减少找工具的时间
  • 次月留存率可统计（这是核心增长指标）

六、关键成功指标（北极星）

P0 阶段（第1周末）：
- 首页跳出率降低（因为用户知道该点哪了）
- 无占位页，所有页面有实质内容

P1 阶段（第3周末）：
- 注册用户数（冷启动种子用户）
- 策展引擎生成报告数 / 采纳率
- 转化CTA点击率（至少有流量进purchase/survey页）

P2 阶段（第4月末）：
- 北极星指标：付费用户数 / 月度经常性收入（MRR）
- 次月留存率（数字员工用得越久，留存越高）
- 报告采纳率（生成质量的核心指标）
💡 给创始人的一句话建议：
P0和P1可以马上启动，1-3周内就能看到效果。P2是战略投入，但也是真正构建壁垒的地方——不要急于求成，先把策展引擎的L2跑通，验证"知识→报告"的生成质量，再投入做数字员工L3。节奏上，第1月止血+建信任，第2月打穿L2，第3月启动L3。
