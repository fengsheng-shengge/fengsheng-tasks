## 二、总体审核原则（七字诀，来自执行手册）

每一条入库内容必须符合**七字诀**，一条不符合打回：

| 字 | 要求 | 典型错误 |
|----|------|----------|
| **系** | 按本体分类，不乱塞 | 把养老院塞进"法规"类 |
| **完** | 每类词条必须挂齐必要字段 | 法规词条无`legalText`原文链接 |
| **全** | 覆盖主要服务对象（老人/子女/机构/护理员） | 只采集护理员视角，缺失家属视角 |
| **准** | 数字/日期/费率双源校验 | 引用政策但无原文链接 |
| **权** | 只认政府官网/红头文件/权威媒体 | 引用自媒体推文作为证据 |
| **真** | 话术来自真实成交或资深经纪人经验 | AI生成话术无来源标注 |
| **实** | 经纪人搜出来能直接用 | 输出晦涩术语而非大白话 |

## 三、Schema审核标准（养老Graph_Schema定义_v1.1）

### 3.1 节点类型规范

三类节点**必须全部包含**，不得缺失：

| 节点类型 | 必须包含的专属字段 | 缺一不可 |
|----------|-------------------|----------|
| **location（居住点）** | `locationType`（CCRC/护理院/社区嵌入式/居家）<br>`bedCount`/`occupancyRate`<br>`accessibilityScore`（0-1）<br>`safetyScore`（0-1）<br>`dignityScore`（0-1） | ✅ |
| **elderly（老人）** | `ltciLevel`（1-5）<br>`mobilityScore`（0-1）<br>`cognitiveScore`（0-1）<br>`dignityPreference`（怀旧/独立/家庭优先）<br>`familyInvolvement` | ✅ |
| **service（服务）** | `serviceType`（医疗/护理/康复/心理/临终）<br>`qualificationRequired`（资质要求）<br>`costStructure`<br>`coverageScope` | ✅ |

### 3.2 四类功能性边规范

| 边类型 | 触发条件 | 审核重点 |
|--------|----------|----------|
| **ADAPT_TO** | `accessibilityScore ≥ 0.7` 且 `safetyScore ≥ 0.7` | 低于任一阈值不得连边 |
| **DIGNITY_MATCH** | `dignityScore`与老人`dignityPreference`匹配度≥0.8 | 怀旧偏好必须关联同类机构 |
| **SAFETY_SUPPORT** | 夜班配比≥1:5 + 跌倒率数据可查 | 无数据支撑不得声称"安全" |
| **TIME_EVOLVE** | 老人状态转移（L3→L4等）必须附医生证明 | 禁止无证明自动演化 |

### 3.3 _visibility字段规范（三层必须固化）

| 层级 | 可见范围 | 审核重点 |
|------|----------|----------|
| `consumer` | 老人/家属直接可见 | 不得含内部定价策略/谈判底价 |
| `service_provider` | 护理员/机构运营可见 | 不得含客户隐私/投诉记录 |
| `internal` | 风声内部可见 | 含成本核算/竞品分析等保密内容 |

**强制检查**：所有词条**必须有**`_visibility`字段，无则为不合格。

### 3.4 两层分类维度（不得混用）

| 维度 | 分类内容 | 错误示例 |
|------|----------|----------|
| **内容形式维度** | 法规 / 案例 / 话术 / 数据 / 流程 | ❌ 把"养老"放在此类 |
| **服务领域维度** | 居住服务 / 养老居住服务 | ❌ 把"话术"放在此类；❌ 把"家装增项"（适老化改造）归入养老居住服务 |

养老是**服务领域**，不是词条类型。任何词条可同时标注两个维度。

**家装/养老边界检查（必查）**：适老化改造（扶手 / 坡道 / 防滑 / 紧急呼叫）是**居住环境适老适配**，属"养老居住服务（D16）"领域；仅纯家装精装升级（非适老性质）属"居住服务"。凡发现"家装增项"被标为"养老优势"，一律打回。

### 3.5 服务对象矩阵（三维必须完整）

```
大居住服务
├── 居住服务
│   ├── 消费者：买房客 / 租房客 / 业主 / 房东
│   └── 服务者：经纪人
└── 养老居住服务
    ├── 消费者：老人 / 子女家属 / 老人+家属（共同决策）
    └── 服务者：护理员 / 机构运营方 / 养老经纪人 / 社区服务者 / 辅具供应商
```

**审核要点**：每个角色大类至少有一条词条对应，无则为不合格。

**边界审核（必查）**：养老居住服务的服务者包含"适老改造服务商"——适老化改造（扶手 / 坡道 / 防滑）属养老居住服务（D16）领域，应归入养老居住服务的服务者。但纯家装精装升级不得归入养老居住服务。

## 四、采集规范审核标准（养老Graph_小马丫采集规范_v1.0）

### 4.1 Trust权重体系（必须严格执行）

| 等级 | 来源 | 权重 | 用途 |
|------|------|------|------|
| **T0** | 政府官网原文 / 法院判决书 | 100% | 可直接引用 |
| **T1** | 权威媒体 / 行业协会白皮书 | 80% | 可引用，需标注来源 |
| **T2** | 专家访谈 / 资深从业者经验 | 60% | 可参考，需注明 |
| **T3** | 自媒体 / 网络论坛 | 30% | 禁止作为主要依据 |
| **T4** | AI生成内容 | 0% | 禁止入库 |

### 4.2 禁止采集清单

以下内容**一律不得采集**：

- 涉诊断/治疗/处方建议（医疗防火墙）
- 未经脱敏的客户个人信息
- 未经授权的竞品内部数据
- 无来源的政策解读
- 主观评价无数据支撑的对比

### 4.3 三类节点采集规格

| 节点 | 必须字段 | 最低边数 |
|------|----------|----------|
| location | 8个核心字段 | ≥2条ADAPT_TO或DIGNITY_MATCH |
| elderly | 7个核心字段 | ≥1条TIME_EVOLVE |
| service | 6个核心字段 | ≥1条SAFETY_SUPPORT |

## 五、API接口审核标准（磐石养老Graph_API接口规范）

### 5.1 医疗防火墙（强制）

以下关键词**自动拦截**，不返回任何结果：

```
diagnosis / 诊断 / 治疗方案 / 处方 / 
用药建议 / 手术建议 / 医疗判断
```

审核时必须用上述词测试接口，确认全部拦截。

### 5.2 权重计算规则

| 维度 | 权重 | 最低门槛 |
|------|------|----------|
| Dignity（尊严匹配） | 40% | ≥0.6可推荐 |
| Safety（安全评分） | 30% | ≥0.7可推荐 |
| Cost（费用） | 20% | 透明展示 |
| Convenience（便利性） | 10% | 参考维度 |

**审核要点**：权重计算公式必须可解释，禁止黑箱。

### 5.3 多形态输出

| 形态 | 触发条件 | 最低质量要求 |
|------|----------|-------------|
| 表格 | `format=table` | 列对齐、数字格式化 |
| PDF | `format=pdf` | 含水印/版本号/生成时间 |
| PPT | `format=ppt` | 每页≤5行，配图≥1 |
| 话术 | `format=script` | 含场景标注/异议处理 |
| 语音 | `format=voice` | 文本先审再转语音 |
