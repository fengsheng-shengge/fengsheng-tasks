# 风声知识底座 · 数据字典与数据生产标准 v1.2.1（补丁版）

一套字段、一套口径、一套流程，所有人统一遵守。解决"数据口径对不上、每人各有一套认知"的问题，让知识底座从碎片化采集走向可调用的生产力。

**本版（v1.2）由 v1.1 草案经全员评审三方收敛（小眼镜/小鱼儿/小豆子）后正式定稿生效。**

| 版本 | 状态 | 签发 | 评审 | 生效 | 适用范围 |
|---|---|---|---|---|---|
| v1.2（正式版） | 生效 | 生哥 · 小眼镜 | 三方收敛：小眼镜 8 条+第5项 / 小鱼儿 P0×3 / 小豆子落库确认 | 2026-08-29 | 小眼镜/小马丫/小豆子/小叮当/小扣子/小酒窝儿 |
| v1.1（草案） | 已归档 | 生哥 · 小眼镜 | 采纳小马丫 11 条建议 | 2026-08-27 | 全员评审通过 |

## ▍总览：这份标准解决什么

一句话：过去的知识底座有 6 份以上分散标准、三套互相不认的字段体系、各 Agent 各按自己理解生产数据，导致口径对不上、总量涨了也难形成生产力。本标准收口为唯一依据。

- 🎯 一份标准：取代全部散落版本，唯一权威，冲突时以本标准为准。
- 🔤 一套字段：统一字段契约 + 旧字段映射表，消除 entryName/name、description/detail 等命名打架。
- 📐 一套口径：数据字典定义每个数据项的指标口径/单位/周期/来源，杜绝同一指标两种说法。
- 🔁 一套流程：采集→格式化→自检→送审→入库→复采 7 步闭环，L1 词条 / L2 数据集各归其位。

**一票否决红线（五项）**
① 无来源不入库：未按本标准生产的任何数据一律不得并入主库；
② 编造零容忍：发现编造，整批退回并记录；
③ 口径未仲裁不入库：多源口径冲突未登记仲裁的不入库；
④ 隐私数据零容忍：含个人可识别信息（PII）的数据一律不得入库（见第九节）；
⑤ 内部口径零外泄（v1.2 新增）：七维/权重/服务线谱系/内部策略词等内部口径一律不得对外暴露（对消费端/外部输出），违反即一票否决、整批退回（见 9.3 内部级管控）。

已入库但字段/口径/合规不合规的，按本标准降级或退回重建。

## 一 · 定位与总则

**1.1 定位**
本标准的定位是风声知识底座的"宪法"——定义知识怎么采集、怎么表达、怎么核验、怎么入库、怎么被消费端调用。它不是建议，是强制执行要求。

**1.2 核心原则**（六大原则，任何一条不满足即不入库）

| 原则 | 含义 | 违反后果 |
|---|---|---|
| 有来源 | 每条知识必须绑定可查证的 source + source_url | 不入库 |
| 有出处 | 数值/结论必须标注采集日或统计周期（asOf / lastVerified） | 降级"示意" |
| 有字段 | 必填 18 项字段齐全，口径与数据字典一致 | 整批退回 |
| 可追溯 | 词条→数据→来源 URL 全链路可反查 | 不入库 |
| 不编造 | 无来源不收，多源冲突并列标注不取单值 | 一票否决，整批退回 |
| 不硬凑 | 采集不到标"待核"，不为了凑数填假值 | 标"待核"合规，硬凑违规 |

**1.3 三道铁律（词条入库门禁）**

| 铁律 | 标准 | 判定 |
|---|---|---|
| 找得到 | 至少 2 个入口可达（搜索/场景/法条/案例） | 达不到不入库 |
| 看得懂 | 标题 3 秒懂、一句话答案 ≤30 字、核心要点每条 ≤20 字 | 达不到不入库 |
| 用得上 | 含可执行动作或可引用依据，不是知识科普 | 达不到不入库 |

## 二 · 统一数据模型：双层结构

知识底座不是"只有词条"的单层锅。按知识形态分两层，各管各的、互相打通——这是解决"碎片塞不进词条库"的根本。

**L1 · 词条层（规则/案例/政策/定义）**
- 回答"怎么办、是什么、有什么风险"——静态、可推理、问答型
- 现有主库 entries_5000.json · 6968 条（OWN/PRE/CAR/LIV/P2/P3/CASE/POL/DEC/RNT/TRX…）。涨量靠新规则与案例，不靠硬塞动态数据。

**⇅ 打通机制：** 词条通过 dataRef 字段引用 L2 数据集（如 dataRef: DS-MKT-001）。消费端运行时"规则查 L1、出数查 L2"——决策引擎要讲理时读词条，要出数时打数据集，各取所长，互不污染。

**L2 · 数据集层（真源动态数据）**
- 回答"现在值多少、通勤多久、哪个板块"——动态、结构化、可查询
- 楼盘 / 市场行情 / 通勤测算 / 学区 / 绿化率 / 案例素材。按数据集登记（见第四节），绑定来源 + asOf，月度更新。

**2.1 总量口径（从此不再混着算）**

| 统计项 | 当前规模（2026-08-27 实查） | 计量口径 |
|---|---|---|
| L1 词条 | 6968 条 | 按词条条数计 |
| L2 数据集 | 6 个 | 按数据集计（内含行数另计） |
| 词条字段 | 53 个（每条实际 25-41） | 统一契约见第三节 |

## 三 · 词条字段契约（统一 Schema）

所有采集 Agent 生产词条时，字段名必须用下表，缺一不收。旧字段名（entryName/description/effDate…）全部作废，映射见附录A。

**3.1 必填 18 项**

| # | 字段 | 类型 | 说明 | 示例 |
|---|---|---|---|---|
| 1 | id | string | 全局唯一，{域前缀}-{场景}-{序号} | POL-021 |
| 2 | domain | string | 数据域 | policy |
| 3 | sceneDomain | string | 场景域 | 签约中 |
| 4 | subScene | string | 子场景 | 资格审查→限购 |
| 5 | name | string | 词条名（客户问法） | 买二套首付比例是多少 |
| 6 | alias | array | 搜索别名 ≥3 | ["二套","首付","贷款比例"] |
| 7 | detail | string | 正文 ≥12 行 | … |
| 8 | source | string | 来源名称 | 住建委官网 |
| 9 | source_url | string | 来源 URL（必须可访问） | https://… |
| 10 | authority | enum | A/B/C 权威等级 | A |
| 11 | trustLevel | number | 0-1 可信度 | 0.85 |
| 12 | entryType | enum | 知识/数据/案例/政策/流程/风险/定义 | 政策 |
| 13 | priority | enum | P0/P1/P2 | P0 |
| 14 | tags | array | 标签 ≥3，且须含 clientType 维度（数组中至少一项含 "client"，v1.2 #227 铁律合入） | ["client","学区","海淀"] |
| 15 | ownerQ | string | 谁问的问题 | 购房者/经纪人 |
| 16 | ownerBenefit | string | 对谁有什么价值 | 帮客户快速判断 |
| 17 | lastVerified | date | 最后核验日期 | 2026-08-27 |
| 18 | caveat | string | 风险提示（无则写"无"） | 各校划片以当年政策为准 |

**3.2 条件必填（按词条类型触发）**

| 字段 | 触发条件 | 要求 |
|---|---|---|
| relation | 所有词条（必填声明，允许空数组） | 词条级关系声明：{type, target}；type∈前置/后置/父子/关联数据集/关联案例；target 指向存在的词条 id 或数据集 dsId，入库校验指向必须存在 |
| legalRef | 涉法词条 | 引用到条文号，如《民法典》第710条 + 发布机关/日期 |
| dataRef | 数据类 / 引用数据的词条 | 引用 L2 数据集 ID 或具体数据链接，不得填"待补充数据"；结构模板 {value, unit, asOf, source}（v1.2 合入） |
| caseRef | 案例类 | 案号 + 法院 + 年份，或可核验来源；结构模板 {desc, caseNo, source}（v1.2 合入） |
| severity | 风险/纠纷类 | hard=法条强制 / medium=标准规范 / soft=行业惯例 |
| consumerQ/consumerBenefit | 可对外展示词条 | 客户问法 + 客户受益点 |
| owner | L1 词条层（全部词条，v1.2 新增） | 词条负责 Agent，明确到人，与 4.2 数据集 owner 口径一致 |
| ola/cp | 服务/费用类 | 服务水平承诺 / 成本价格参考 |
| toolType | 工具卡类 | 决策卡/流程卡/评估卡/校准卡/风险卡/边界卡 |
| asOf | L2 数据集条目 | 数据截止/采集日期，格式 YYYY-MM-DD |

**3.3 可选字段**
def、simpleAnswer、posSpeech、negSpeech、attrs、srcType、scene、riskStage、accountability、relatedEntries、fdeChain、ownerCard、source_type、source_url_note 等。可选字段同样遵循"填了就必须真实、绑来源"。

## 四 · 数据字典（L2 数据集口径规范）

数据字典 = L2 数据集的"注册中心"。任何动态数据入库前，必须先在这里登记口径，否则视为无标准数据、不予采用。这是解决"同一指标两种说法"的根治手段。

| 要素 | 字段 | 要求 |

| 编号 | dsId | DS-{类别}-{序号} |

## 五 · 采集生产流程（7 步闭环）

所有数据生产必须走完 7 步，缺一步不算完成。品控复核贯穿第 5 步，形成 采集 → 入库 → 品控 → 消费 全程闭环。

| 步骤 | 动作 | 要点 |
|---|---|---|
| STEP 1 立项 | 明确采集方向/范围/颗粒度 | 登记数据集编号与口径（dsDef 先行） |
| STEP 2 采集 | 按真源采集 | 数值绑 source_url + asOf，多源冲突并列标注 |
| STEP 3 格式化 | 转统一字段契约 | L1 用 3.1/3.2，L2 用 4.2，旧字段名作废 |
| STEP 4 自检 | 3 轮自检 0 错误 | 字段齐/来源可查/时效达标/无编造 |
| STEP 5 送审 | 提交小眼镜核验 | + 独立 API 抽验（数值类如高德/官方口径）+ 品控复核（小酒窝儿） |
| STEP 6 入库 | L1 词条并入 entries 主库 | L2 数据集登记入数据字典，随版本管理 |
| STEP 7 复采/版本 | L2 增量留史、全量出数 | 重采先留历史快照；**版本号与 asOf 强制绑定**（记录版本号+数据截止日，v1.2 升级为强制措辞），禁止静默覆盖 |

**入库前提：** 未完成第 5 步核验的数据，一律标"待核"，不得进入任何对外/消费端输出。核验通过才可升"已核验"。

## 六 · 质量门槛

**6.1 权威分级（统一双轨制）**

| 等级 | trustLevel | 来源类型 | 入库要求 |
|---|---|---|---|
| A | ≥ 0.85 | 法律条文/司法解释/政府文件/官方数据 | 标注发布机关+文号+日期，可直接引用 |
| B | 0.75-0.85 | 行业协会/权威机构/主流媒体/学术论文 | 需标注"交叉验证" |
| C | 0.65-0.75 | 行业报告/一般媒体 | 必须双源验证才可入权威引用 |
| <C | < 0.65 | 个人经验/自媒体/论坛 | 不入库；或仅作"示意"并明确标注 |

**双轨一致性硬校验：** authority 与 trustLevel 必须落在对应区间（A≥0.85 / B 0.75-0.85 / C 0.65-0.75 / <C 0.65）。出现越界（如 authority=B 却 trustLevel=0.9）：以 authority 为准，整批退回修正后重审。验收表同步执行（见第八节）。

**6.2 其他门槛**

| 维度 | 标准 |
|---|---|
| 双源验证 | 关键数据至少 2 个独立来源；单源数据 trustLevel 上限 0.65，并附 URL |
| 时效性 | 政策/法规类优先当年；数据类 3 年内；超期标 asOf，禁止当现价引用 |
| 编造零容忍 | 发现编造，整批退回并记录 |
| 字段质量 | detail 正文 ≥400 字且 ≥3 个要点条目（内容尺度，非行数）；alias ≥3；tags ≥3；name 是客户问法 |
| 证据链 | dataRef/caseRef 为真实引用，禁止"待补充数据/待补充案例"占位符 |

## 七 · 消费端降级规则

知识库的"生产力"最终体现在消费端输出。规则：宁可"示意"，不出无依据硬数。

| 情形 | 处理 |
|---|---|
| 数值无 source_url | 不渲染权威数值卡，降级"示意" |
| dataRef / caseRef 未补齐 | 按"示意"执行，不出权威硬数 |
| demo / 内部参考 | 明确标注"示意"，不进正式输出 |
| 多源口径冲突 | 并列标注，不合并取单值 |
| 数据已过期 | 标注 asOf，禁止当现价引用 |
| 数据集未核验（status=待核） | 禁止进消费端权威引用 |

**升级闭环（示意 → 已核验）：** 降级不是终点：补齐缺失字段 → 重新送审 → 独立抽验通过 → 升"已核验"进入权威引用。双向闭环，数据不因一次缺失永久降级。

**当前落地口径（已核实）：** 6968 库中真实内容 dataRef 仅 19.1%、caseRef 仅 13.3%——按本标准，这些词条在消费端一律降级"示意"，不输出权威数值卡，待补齐后再升级。

## 八 · 验收标准

| 验收项 | 标准 | 检查方式 |
|---|---|---|
| 字段完整性 | 必填 18 项 100% 齐全 | 脚本校验 |
| 来源可查 | source_url 100% 可访问 | 抽验 ≥20% |
| 时效达标 | lastVerified 不超过 90 天 | 脚本校验 |
| 口径一致 | 数据字典 dsDef 无歧义，跨 Agent 抽查一致率 100% | 交叉核验 |
| 编造零容忍 | 0 条编造 | 独立 API/口径抽验 |
| 证据链可用 | dataRef/caseRef 无占位符 | 全量扫描 |
| 找得到/看得懂/用得上 | 三道铁律全过 | 入库门禁 |
| 双轨一致性 | authority 与 trustLevel 区间匹配，0 越界 | 脚本硬校验，越界整批退回 |

## 九 · 数据合规与安全

标准不只管"对不对"，还要管"能不能碰"。数据采集、存储、生产、消费全链路设防，隐私与敏感数据零容忍。

**9.1 隐私红线（一票否决第 4 项）**
零容忍任何含个人可识别信息（PII）的数据——姓名+联系方式、身份证号、精确门牌、车牌、人脸、家庭资产明细、家庭关系等——一律不得入库，无例外。谁碰谁违规，整批退回并追责到负责人。

**9.2 敏感字段禁采清单（校验器硬编码拦截）**

| 类别 | 禁采/禁存内容 | 合规替代 |
|---|---|---|
| 个人身份 | 姓名+联系方式、身份证号、证件照片 | 仅存"客户/经纪人"角色与需求维度，不存可识别身份 |
| 精确位置 | 精确门牌号、家庭住址、车牌、人脸 | 存到板块/小区粒度，不存精确坐标 |
| 资产隐私 | 家庭资产明细、收入流水、债务信息 | 仅存决策相关维度（预算区间/持有周期），脱敏处理 |
| 内部敏感 | 客户购房动机、谈判策略、独家判断原稿 | 敏感级管控：加密 + 权限白名单 + 输出脱敏 |

**9.3 数据分级管控**

| 级别 | 内容 | 管控 |
|---|---|---|
| 公开级 | 公开挂牌/市场/政策/法规数据 | 全 Agent 可共享，入库前仍须过来源与口径校验 |
| 内部级 | 风声协作方内部数据 | 仅飞书协作群内可见，不对外输出；**内部口径（七维/权重/服务线谱系/内部策略词）一律不得对外暴露，违者触发一票否决第5项（v1.2）** |
| 敏感级 | 客户需求画像、案例脱敏前素材、内部判断 | 加密 + 权限白名单 + 输出脱敏 |
