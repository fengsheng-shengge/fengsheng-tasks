## 〇、文档目的与背景

### 0.1 为什么需要 V2.0 专属测试策略

风声小程序 V2.0 正在重设，产品方向从**「数据展示型」**转变为**「场景工具型」**。这不是 UI 改版，而是信息架构、交付逻辑、用户旅程的根本性翻转。沿用 V1（5Tab 数据展示型）的测试思路会导致：

- 测了「页面能打开」但漏了「场景闭环能用」
- 测了「数据加载」但漏了「器（可交付物）能发客户」
- 测了「功能点」但漏了「道法术器四层不跳层」

本框架对齐 V2.0 新架构，确保测试覆盖**场景驱动 × 道法术器四层 × 器可交付**这一核心逻辑。

### 0.2 V2.0 核心变化（测试必须对齐）

| 维度 | V1（数据展示型） | V2.0（场景工具型） | 测试影响 |
|---|---|---|---|
| 产品方向 | 从数据出发（有什么数据展示什么） | 从场景出发给工具（经纪人面对客户需要什么） | 测试从「功能点遍历」转向「场景闭环验证」 |
| 信息架构 | 5Tab 展示型（首页\|词典\|导师\|测评\|我的） | 5Tab 工具型（首页场景入口\|词典全量+收藏\|导师预留\|测评游戏化保留\|我的积分/贡献） | Tab 结构保留壳但重排优先级，首页+词典为核心，导师/测评为占位 |
| 词典 | 独立 Tab 主推 | 工具内「知识速查」浮层（Tab 保留全量浏览） | 浮层调用逻辑 + 三维标签过滤需重点测 |
| 导师 | Tab 独立功能 | P0 不上，显示「专业导师即将开放」占位 | 导师 Tab 仅测占位文案 + 不可交互 |
| 测评 | 独立 Tab | 游戏化保留，场景完成后巩固测验触发 | 测评 Tab P0 仅测占位 + 触发时机 |
| 积分 | 核心功能 | P2 远期 | 积分相关降级为冒烟级 |
| MVP 范围 | 全功能铺开 | 买房客户 × 3 个 P0 场景 | 测试聚焦 3 场景闭环，其余降级 |

### 0.3 道法术器四层框架（测试基线）

每个场景按 **道 → 法 → 术 → 器** 四层交付，测试必须验证「四层齐全、顺序固定、不跳层」：

| 层 | 经纪人视角 | 交付内容 | 测试红线 |
|---|---|---|---|
| **道**（规律） | 他到底什么意思 | 一句话规律 / 人性洞察 | 不直接给话术 |
| **法**（方法） | 我下一步怎么做 | 当场动作步骤 / checklist | 不跳过方法直接给模板 |
| **术**（话术） | 我嘴上怎么开口 | 按场景的原话话术 | 不堆大杂烩话术 |
| **器**（工具） | 我能给客户看什么 | 可带走 / 可分享的交付物 | 不绑定小程序，能单独发客户 |

> **器是可带走的交付物**——测评卡、对比表、清单，是「拿来直接服务消费者」的落点。**器的生成 / 预览 / 分享流程是 V2.0 测试的最高优先级**（详见第五章）。

## 一、测试范围

### 1.1 In Scope（本策略覆盖）

**P0 — MVP 必测（买房客户 × 3 场景闭环）** — 对齐小豆子 7.25 确认方案

1. 首页场景入口：选「服务谁」→ 选「到哪步」两级选择（买房客户激活，其余标「即将开放」）
2. 客户解码工具页（买房·售前）—— 道法术器 + 客户在场场景卡 + 器层交付物卡
3. 带看服务工具页（买房·售中）—— 同上
4. 谈判斡旋工具页（买房·售中）—— 同上
5. 工具内「知识速查」浮层（按 场景×阶段×层次 调词条）
6. 器层「发客户 / 复制」动作（交付物即用）
7. 词典 Tab 全量浏览 + 收藏（保留既有，作为浮层补充）
8. 品牌定位语升级（获得尊重 + 在客户面前掏出手机就能用）
9. 埋点（复用已设计 7 事件：content_click / expand / collect / followup + trigger_*）
10. 技术约束合规（主包大小、JSON 加载、WXML 转义、路径规范、编译配置）
11. 已知 V2.0 bug 回归（6 项，详见第六章）
12. 5Tab 结构完整性（首页/词典可用 · 导师/测评占位 · 我的可用）

**P1 — 冒烟级（不展开用例，仅验证不崩溃）**

- 出售业主 / 租房客户场景入口（标「即将开放」）
- 导师 Tab 占位（显示「专业导师即将开放」，不可交互，不崩溃）

- 积分体系完整流程（P2 远期，仅冒烟）

- 导师对话流驱动（依赖 T07 dialog_flow_map.json，8.8 前）

## 二、测试分层策略

V2.0 采用三层测试金字塔，自下而上覆盖，重点在集成层与 E2E 层（场景工具型产品价值在端到端闭环中体现）。

### 2.1 单元测试（Unit）

**目标**：验证独立函数 / 组件 / 数据映射逻辑的正确性。

| 模块 | 测试对象 | 关键用例方向 | 文件位置 |
|---|---|---|---|
| 数据映射 | `build_entries.mjs` | subScene→场景组映射正确；tags.layer→etype 映射正确；总数=570；无未命中兜底 | `prototype/build_entries.mjs` |
| 积分 / 配额 | `store/user.js` | earnPoints/spendPoints/unlockContent 余额计算；checkQuotaBeforeSendMessage 跨日重置；consumeQuota 边界 | `fs-mini-program/src/store/user.js` |
| 等级计算 | `getLevelInfo()` | 各积分区间等级名正确；边界值（0/100/300/...） | `fs-mini-program/src/store/user.js` |
| 搜索匹配 | `searchEntries()` | 词条名匹配 + 别名匹配 + 去重合并 | 词典页逻辑 |
| 词条时效 | 时效标注逻辑 | srcType 含「法律/行政法规…」时显示验证条；已废止法条标注 | `entry-detail.vue` |
| SSE 解析 | `parseSSE()` | `data:` 行解析；`[DONE]` 收尾；conversation_id 提取 | `mentor/index.vue` |

**单元测试准入标准**：核心纯函数（积分计算、等级判定、数据映射）单测覆盖率 ≥ 80%。

### 2.2 集成测试（Integration）

**目标**：验证模块间协作、数据流、页面跳转、API 调用链路。

| 集成点 | 测试重点 | 优先级 |
|---|---|---|
| 首页 → 工具页跳转 | 两级选择后正确进入对应场景工具页，参数传递正确 | P0 |
| 工具页 → 知识速查浮层 | 按 场景×阶段×层次 三维过滤词条，浮层词条数符合数据基线 | P0 |
| 工具页 → 器层交付物生成 | 「发客户 / 复制」触发交付物卡片生成，内容来自真实数据 | P0 |
| 器层 → 分享 / 复制 | 分享卡片弹出且不与生成浮层叠层；复制写入剪贴板 | P0 |
| 词典 Tab ↔ 浮层共存 | Tab 全量浏览与浮层按需调取互不干扰 | P0 |

| 埋点链路 | 7 事件在正确时机触发，本地存储写入正常 | P0 |
| 词条解锁链路 | 积分扣除 → 内容展开 → unlockedContent 持久化 | P1 |
| 大 JSON 加载 | entries.json（500KB）加载方式正确，不触发 require 限制 | P0 |

### 2.3 端到端测试（E2E）

**目标**：从经纪人视角验证完整场景闭环，复用 PR#189 已验证的 Playwright 自动化框架（`prototype/verify/`）。

E2E 测试是 V2.0 的**核心测试层**，因为「场景工具型」的价值只有在端到端闭环中才能验证。

**E2E 三遍测试法（继承交付铁律「真跑 3 遍」）**：

| 遍次 | 视口 | 重点 |
|---|---|---|
| 第 1 遍 | 桌面 1280×800 | 打开 + 截图 + 抓 console 错误 + 品牌语校验 |
| 第 2 遍 | 桌面 420×880 | 点所有交互 + 浮层/弹窗 + 器层交付物流程 + Tab 切换 |

**E2E 准入标准**：3 遍全绿、0 console 错误、0 横向溢出、关键截图齐全。

## 四、关键测试场景（3 个 P0 场景 × 道法术器）

> 本章是 V2.0 测试的核心。每个场景按「场景入口 → 道法术器四层 → 器层交付物流程」结构展开。
> **器的生成 / 预览 / 分享流程是最高优先级**，详见每场景第 4 节。

### 4.1 场景一：客户解码（买房客户 · 售前）

**场景入口测试**
- 首页选「买房客户」chip 激活 → 选「售前」阶段 → 显示「客户解码」场景卡
- 售前阶段仅 1 张卡（客户解码），售中 2 张（带看 + 谈判），售后显示空态
- 点场景卡 → 进入 `客户解码` 工具页

**道层（先懂，不慌）**
- 内容：客户说「再看看」三大顾虑（怕买贵 / 怕踩坑 / 怕后悔）；决策是情绪曲线
- 测试：道层 section 存在、内容非空、不直接给话术（红线）

**法层（当场怎么走）**
- 内容：听原话 → 拆顾虑 → 对画像 → 给标准 四步
- 测试：法层为 checklist 形态、步骤可展开、不跳过方法直接给模板（红线）

**术层（嘴上怎么说）**
- 内容：针对「再看看 / 有点贵 / 要和家人商量」三句话术
- 测试：术层话术按场景给、不堆大杂烩（红线）

**器层（直接发给客户的交付物）—— 重点**

| 交付物 | 生成方式 | 预览 | 分享 |
|---|---|---|---|
| 需求挖掘七问模板 | 工具页内置，点击生成 | 预览浮层含客户视角 + 来源 | 发客户 / 复制 |
| 客户画像卡（预算/家庭/时间窗/决策人） | 当场生成，客户确认 | 预览浮层呈现客户视角（.wechat）+ 来源（.src） | 「发客户」→ 弹「客户进展」反馈卡；选「成交了」+50 积分并写入贡献 |
| 六维测评卡 | 把「再看看」变成可看数据 | 预览浮层 | 「发客户」→ toast「已发送给客户」→ 客户进展反馈卡弹出 |

### 4.2 场景二：带看服务（买房客户 · 售中）

**场景入口测试**
- 首页选「买房客户」→ 选「售中」阶段 → 显示「带看服务」「谈判斡旋」2 张卡
- 点「带看服务」→ 进入工具页

**道层**
- 内容：带看是管理客户决策体验（首看定调，复看定心）；客户记不住参数只记得「感觉被懂」

**法层**
- 内容：带看前（房源匹配+动线设计+痛点预设）→ 带看中（动线引导/价值点植入/竞品对比）→ 带看后（24h 跟进+决策窗口）三段
- 测试：三段 checklist 齐全

**术层**
- 内容：动线话术、价值点话术、竞品对比话术
- 测试：话术按场景给

**器层（交付物）—— 重点**

| 交付物 | 生成方式 | 预览 | 分享 |
|---|---|---|---|

| 动线脚本（首看/复看各一版） | 工具页内置 | 预览浮层 | 发客户 / 复制 |

### 5.4 器层流程跨场景一致性

所有 3 个 P0 场景的器层交付物流程应保持一致的交互范式：

```
统一范式：
  点击器层按钮(data-act="send"|"preview"|"copy")
    → 生成预览浮层(#genModal, 含 .wechat 客户视角 + .src 来源)
      → [发客户] → toast「已发送给客户」→ 客户进展反馈卡(#afterSendSheet)
      → [采集反馈] → 贡献反馈浮层(#contribOverlay)
      → [复制] → toast「已复制」
      → [分享卡] → 分享浮层(#shareOverlay)，生成浮层关闭
```

测试需验证 3 个场景均遵循此范式，交互不一致即视为缺陷。

3. **器可交付**：每个器层交付物必须验证「能发客户 / 能复制 / 不绑定小程序」
4. **不跳层**：道法术器四层顺序固定，测试验证不跳层
