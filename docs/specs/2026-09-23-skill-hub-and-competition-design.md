# 服务者技能训练考核 + 技能大赛 设计文档

> 日期：2026-09-23
> 状态：待源码接入后实施
> 目标站：贝壳杯大赛站（http://81.70.181.118/，源码待接入工作区）

## 一、背景与目标

在现有赛事站点内新增两大功能模块，服务对象为**产业工人、一线服务者**（区别于风声主站的 AI 数字员工考核）。

核心设计原则（用户明确要求）：
1. **弱化贝壳元素**——赛事命名、视觉、叙事均向"产业工人/一线服务者"倾斜，不突出品牌方。
2. **对标世界技能大赛逻辑**——标准先行、以考定级、以赛证技。
3. **以赛促学、以赛提技**——训练与大赛数据相通，日常积累推动参赛与提升。

## 二、模块定位与关系

同一站点（服务技能中心）下的两个**并列子功能**，共用一套用户体系、工种体系、数据模型。

```
服务技能中心
├── 日常训练考核（训练 + 等级认证）
└── 技能大赛（对标世赛）
```

- **核心定位**：日常训练 + 等级认证模块。
- **工种范围**：扩展到**全部服务岗位**（不限于现有六大施工工种，作为可扩展的工种档案体系）。
- **认证机制**：积分升等级 + 专项技能认证章，**两者结合**。
- **训练形式**：在线答题 + 案例学习。
- **题库来源**：复用风声知识库题库（`data/game_judge_quiz.json`、`data/game_client_simulator.json`、`entries.json`、`scene_cards.json`、`case_library.json`）。

## 三、架构设计

### 3.1 总体结构

独立站点形态（完整独立站点，非仅加两个页面），包含首页入口 + 两大模块页 + 数据层。

### 3.2 模块划分

| 单元 | 职责 | 依赖 |
|---|---|---|
| 服务技能中心首页 | 两大模块入口、全局数据总览 | 用户、工种、统计 |
| 日常训练考核模块 | 在线答题、案例学习、积分、等级、认证章 | 题库、用户档案、工种体系 |
| 技能大赛模块 | 大赛信息、报名、作品、打分、排名 | 用户、工种、作品库 |
| 用户/工种体系 | 统一的用户档案与工种档案数据 | 无 |
| 数据层 | 题库、案例、用户档案、作品、成绩的存储 | 无 |

### 3.3 数据流

- 用户注册/上报工种 → 建立服务者档案
- 日常学习答题/看案例 → 积分累加 → 触发等级晋升 + 技能认证章授予
- 训练档案可直接用于大赛报名（预选资格依据）
- 大赛打分结果回写用户档案（提升等级/认证权重）

## 四、数据模型（草拟）

### 4.1 用户（服务者）档案
```
user {
  id, name(昵称/化名), role(岗位/工种), city,
  level(当前等级: 初级/中级/高级/师级),
  exp(总积分), badges[](已获认证章),
  joinDate, source(渠道)
}
```

### 4.2 工种体系
```
trade {
  id, name, category(工种分类), description,
  skillTags[](技能指标标签),
  certifications[](该工种可认证的专项章)
}
```
覆盖范围扩展到全部服务岗位，以 `category` 分组做可扩展设计。

### 4.3 题库
复用风声题库结构：
- `game_judge_quiz`（判断题，带 correctOption + 法律依据/专业洞察）
- `game_client_simulator`（场景选择，带方法论/半法/话术/错误四级评分）
- 新增训练场景可继续扩充；后续内容团队补充各岗位专属题。

### 4.4 训练记录 / 积分
```
studyLog {
  userId, tradeId, kind(答题/案例/实操), itemId,
  result, expGained, timestamp
}
```
等级晋升规则（草拟）：累计 exp 达阈值自动升级；专项认证依据 skillTags 覆盖度授予对应认证章。

### 4.5 大赛模块（复用贝壳杯既有六角流程）
- 报名、作品上传、裁判打分（四大模块）、排名、管理。
- 弱化贝壳品牌文案，中立化赛事命名与视觉。
