# 风声网站首页重构设计文档

> 版本：v1.0 | 日期：2026-08-08 | 状态：待实现

---

## 一、问题背景

当前首页存在 3 个核心问题：

1. **定位不清晰** — 用户一进网站不知道"这是给谁用的、做什么的"
2. **功能平铺无逻辑** — 所有功能入口散落，没有按使用场景组织
3. **缺少引导路径** — 新用户不知道第一步该做什么，只能挨个去点

## 二、产品定位

**风声 = 居住服务者的专业基础设施**

让每个居住服务者（经纪人/物业管家/验房师/装修顾问等），在任何服务场景下，都能查得到知识、找得到方法、用得上工具。

### 3.3 快速场景选择器

**交互流程：**
1. 用户选择客户类型（买房/租房/房东出租/业主出售/经纪人）
2. 用户选择阶段（前期/中期/后期）
3. 系统实时显示该场景下的匹配词条数量
4. 点击场景标签可跳转到 /scene 详情页

**数据来源：** 前端根据 entries.json 的 clientType + stage 字段做本地过滤统计。当前 clientType/stage 字段为空，故先展示 mock 数据，后续数据填充后自动激活。

## 四、UI 设计原则

1. **按钮优先** — 所有功能入口用大按钮 + 图标 + 数据标签，不用文字链接
2. **文字精简** — 每个功能按钮只配一句话说明（≤15字）
3. **视觉层次** — 4 个核心按钮用 2×2 网格，场景选择器独立区域，数据概览在底部
4. **响应式** — 移动端 2×2 网格变为 1 列，场景选择器按钮换行
5. **品牌色系** — 沿用现有风声绿色 #2C5F3A 为主色，橙色 #E8742C 为强调色

## 五、技术实现要点

### 5.1 CSP 修复确认
- 保留 meta CSP 中的 `'unsafe-inline'`，确保内联脚本正常执行

### 5.2 场景选择器数据
- 当前 entries.json 中 clientType/stage/layer 字段为 0%，先展示 mock 数据
- 后续数据填充后，通过 API 获取实时统计

### 5.3 现有功能保留
- 浮动聊天按钮（chat-fab）保留
- 反馈组件移到首页底部，保持简洁
- 合作意向浮层保留
- 全站数据追踪器保留
