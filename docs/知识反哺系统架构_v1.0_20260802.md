# 知识反哺系统架构 v1.0

> 日期：2026-08-02 | 状态：建设中
> 核心理念：知识库不是仓库，是项目的记忆中枢

## 1. 系统目标

让知识库从"被动存储"升级为"自驱动知识引擎"：
- **自己收集**：3条巡采线每日自动搜索行业动态
- **自己筛选**：权威度+相关性+增量三重门禁
- **自己优化**：LLM结构化提炼，映射到风声7+1场景域
- **自己沉淀**：写入坚果云知识库对应目录
- **自己推荐**：主动推送重要发现给项目和生哥

## 3. 后处理管道

### 3.1 知识缺口映射
- 读取巡采简报 → 提取关键发现
- 对比entries_5000.json现有词条 → 识别三类缺口：
  - **时效性缺口**: 现有词条legalRef中的法条已更新 → 标记caveat需更新
  - **覆盖缺口**: 新法规/新概念在知识底座中无对应词条 → 触发补产
  - **深度缺口**: 现有词条只有标准层无深度层 → 评估是否需补充

### 3.2 沉淀到坚果云
- 高价值发现 → 写入`/风声协作/风声知识库/Inbox/巡采/`目录
- 按巡采线分子目录：`政策法规/`、`行业竞品/`、`AI方法论/`
- 文件命名：`YYYY-MM-DD_关键词摘要.md`
- 更新MANIFEST.md索引

### 3.3 飞书推送
- 每日巡采完成后推送综合摘要到飞书群
- 推送格式：
  ```
  📡 风声知识巡采日报 | YYYY-MM-DD
  
  🔴 高优先级（需立即关注）
  - [发现1] 影响范围 + 建议行动
  
  🟡 中优先级（值得了解）
  - [发现2] 关联场景 + 参考
  
  🟢 低优先级（背景参考）
  - [发现3] 归档位置
  ```

### 3.4 项目推荐
- 评估发现与当前活跃GitHub Issue的关联度
- 高关联发现 → 自动推Issue评论
- 映射关系：
  - 政策法规 → #186(标签) + #184(页面)
  - 竞品动态 → #184(产品) + #185(重设)
  - AI方法论 → #179(开发) + #185(重设)

## 4. 自进化闭环

```
巡采发现 → 知识缺口映射 → 三类行动：
  ①词条更新：legalRef/caveat时效性修正 → 送审 → 部署
  ②词条新增：新概念/新法规词条生产 → 送审 → 部署  
  ③产品影响：竞品/技术发现 → 推项目Issue → 产品迭代

用户反馈(小豆子采集) → 巡采方向微调
生哥关注点变化 → 巡采关键词更新
```

## 5. 质量保证

### 5.1 筛选三重门禁
1. **权威度**: 来源必须是官方/权威媒体/学术期刊
2. **相关性**: 与风声7+1场景域有明确映射
3. **增量性**: 与5067条现有词条和既往巡采报告不重复

### 5.2 推送克制原则
- 不是每条发现都推送，只有影响词条时效性或产品决策的才推
- 低优先级发现只归档不推送，避免信息轰炸
- 连续3天空结果自动降频（从日更→隔日→周更）
