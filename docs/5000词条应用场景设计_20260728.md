# 风声知识底座 · 5000词条应用场景设计

> 核心：5000条词条怎么在网站和小程序上被经纪人"找到、看懂、用上"
> 不是"怎么展示数据"，是"经纪人在客户对面时，怎么3秒拿到他要的弹药"
> 小眼镜 · 2026-07-28

---

## 零、设计铁律（从已有共识继承）

| 铁律 | 含义 |
|------|------|
| 场景驱动不数据驱动 | 入口是"我在服务谁、到哪一步"，不是"我有什么功能" |
| 3秒测试 | 3秒看懂标题+3秒理解结论+3秒知道下一步 |
| 五入口可达 | 同一条词条至少5种方式能找到，不允许死胡同 |
| 道法术器不跳层 | 每个回答按 道→法→术→器 给，不直接跳到话术 |
| 器是可带走的 | 终点是一份能发给客户的东西 |
| 不恐吓客户 | 正向案例展示"做对了→好结果"，负向案例聚焦"缺失什么动作" |

### 1.2 经纪人的真实工作节奏

经纪人的时间不是"坐下来慢慢查资料"，而是：

| 时刻 | 他在干什么 | 他需要什么 | 留给他操作的时间 |
|------|-----------|-----------|----------------|
| **见客户前5分钟** | 翻笔记、想话术 | 快速过一遍这个场景的关键判断点 | 3分钟 |
| **跟客户聊天中** | 对面坐着人，手机放桌上 | 一句话结论+法条佐证，不能翻来翻去找 | 3秒 |
| **客户走了之后** | 整理跟进、规划下一步 | 完整的方法论+流程，深挖细节 | 10-30分钟 |
| **碎片时间刷手机** | 等客户、等反馈 | 轻量学习：案例、风险提醒、新政策 | 随手翻 |

**设计原则：不同时刻给不同深度的内容，不要在3秒场景塞3分钟内容。**

### 3.4 语音速查（P0差异化能力）

经纪人最常见场景：**客户问了个问题，他手头忙，没法打字搜索**。

```
┌───────────────────────┐
│                         │
│     🎤 按住说话          │
│                         │
│  "客户说定金能不能退"    │
│                         │
│  ── 3秒后 ──             │
│                         │
│  💡 定金vs订金完全不同   │
│  定金不可退，订金可退     │
│  ⚖️《民法典》§587        │
│  ⚠️ 签的收据上写的字决定  │
│                         │
│  [展开] [发客户] [收藏]  │
│                         │
└───────────────────────┘
```

**实现方式**：
- 语音输入 → ASR转文字 → 意图识别（匹配consumerQ/alias） → 返回top1词条的速查卡
- 匹配不到精确词条 → 返回最相关场景页
- 这是"主动触发"的P0实现：不需要经纪人打字，说出来就能查

## 四、五入口可达设计

5000条词条，同一条词条至少5种方式能到达：

| 入口 | 网站端 | 小程序端 | 触发场景 |
|------|--------|---------|---------|
| **① 场景导航** | 选客户类型→选阶段→进场景→看词条 | 同左 | 经纪人知道自己在什么场景 |
| **② 搜索** | 全局搜索框（支持name+alias+consumerQ） | 搜索框+语音搜索 | 经纪人有明确问题 |
| **③ 主动推送** | 首页"今日速递"+站内通知 | 首页"今日速递"+微信服务通知 | 系统识别到跟经纪人相关的新变动 |
| **④ 关联跳转** | 词条详情页"相关词条"+道法术器同层跳转 | 同左 | 在看A词条时发现B更相关 |
| **⑤ 历史与收藏** | 最近浏览+收藏夹+搜索历史 | 同左（简化版） | 之前看过、反复用的 |

**杜绝死胡同**：每个词条底部必有"相关词条"链接，每条至少关联1-3条。

## 五、网站 vs 小程序 差异化策略

| 维度 | 网站 | 小程序 |
|------|------|--------|
| **使用场景** | 坐下来用：准备、复盘、深入学习 | 站着用：见客户、在带看、在谈判 |
| **内容深度** | 完整展示，可展开可折叠 | 速查优先，默认3秒版 |
| **搜索方式** | 文字搜索+高级筛选 | 文字+**语音搜索**（P0差异） |
| **词条展示** | 完整详情页（所有字段） | 速查卡（一句话+要点+法条+边界） |
| **器层交付** | 在线生成+下载PDF/图片 | 一键生成+**微信分享卡片** |
| **主动触发** | 站内通知+邮件 | **微信服务通知+首页速递** |
| **全量浏览** | 词典Tab：6维筛选+批量导出 | 词典Tab：简化版场景+类型筛选 |
| **团队协作** | 分享链接+团队空间 | 分享微信卡片 |
| **特色功能** | 标签管理+批量导出+深度阅读 | 语音速查+LBS场景识别+离线收藏 |

### 5.1 小程序独有能力

1. **语音速查**：按住说话→3秒出结论。经纪人没法打字时的唯一解法
2. **微信分享卡片**：器层交付物直接生成微信分享卡，发给客户或同事
3. **LBS场景识别**（P1）：检测到经纪人在小区/售楼处 → 自动推送该场景词条
4. **离线收藏**：常用词条收藏后可离线查看，信号不好时也能用
5. **微信服务通知**：政策变动/风险提醒直接推到微信，不需要打开小程序

### 5.2 网站独有能力

1. **全量词典+6维筛选**：场景域×子场景×类型×难度×层级×优先级
2. **批量导出**：选中词条导出为PDF/Excel，供团队培训使用
3. **深度阅读模式**：同一场景下词条连续阅读，像翻书一样
4. **团队空间**：团队标注+共享收藏+内部笔记

## 六、搜索系统设计

### 6.1 匹配字段优先级

```
搜索query → 匹配优先级：
1. name（标题精确匹配）     → 权重10
2. alias（别名精确匹配）    → 权重9
3. consumerQ（客户问法）    → 权重8
4. ownerQ（业主问法）       → 权重7（仅OWN域）
5. oneLineAnswer（一句话答案）→ 权重5
6. corePoint（要点关键词）  → 权重4
7. def（定义/描述）         → 权重3
8. legalRef（法条引用）     → 权重2
```

### 6.2 搜索结果排序

1. 优先级权重分：P0=3, P1=2, P2=1, P3=0
2. 难度权重分：hard=3, medium=2, soft=1
3. 匹配权重 × 优先级权重 × 难度权重 = 最终排序分

**结果**：经纪人搜"押金退还"，P0的hard词条排在最前面，因为这是最需要他第一时间知道的事。
