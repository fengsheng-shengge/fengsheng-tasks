▍总览：这份标准解决什么

一句话：过去的知识底座有 6 份以上分散标准、三套互相不认的字段体系、各 Agent 各按自己理解生产数据，导致口径对不上、总量涨了也难形成生产力。本标准收口为唯一依据。

  • 🎯 一份标准：取代全部散落版本，唯一权威，冲突时以本标准为准。
  • 🔤 一套字段：统一字段契约 + 旧字段映射表，消除 entryName/name、description/detail 等命名打架。
  • 📐 一套口径：数据字典定义每个数据项的指标口径/单位/周期/来源，杜绝同一指标两种说法。
  • 🔁 一套流程：采集→格式化→自检→送审→入库→复采 7 步闭环，L1 词条 / L2 数据集各归其位。

一票否决红线（五项）

① 无来源不入库：未按本标准生产的任何数据一律不得并入主库；

② 编造零容忍：发现编造，整批退回并记录；

③ 口径未仲裁不入库：多源口径冲突未登记仲裁的不入库；

④ 隐私数据零容忍：含个人可识别信息（PII）的数据一律不得入库（见第九节）；

⑤ 内部口径零外泄（v1.2 新增）：七维/权重/服务线谱系/内部策略词等内部口径一律不得对外暴露（对消费端/外部输出），违反即一票否决、整批退回（见 9.3 内部级管控）。

已入库但字段/口径/合规不合规的，按本标准降级或退回重建。

一定位与总则

1.1 定位

本标准的定位是风声知识底座的"宪法"——定义知识怎么采集、怎么表达、怎么核验、怎么入库、怎么被消费端调用。它不是建议，是强制执行要求。

1.2 核心原则（六大原则，任何一条不满足即不入库）

原则含义违反后果
有来源每条知识必须绑定可查证的 source + source_url不入库
有出处数值/结论必须标注采集日或统计周期（asOf / lastVerified）降级"示意"
有字段必填 18 项字段齐全，口径与数据字典一致整批退回
可追溯词条→数据→来源 URL 全链路可反查不入库
不编造无来源不收，多源冲突并列标注不取单值一票否决，整批退回
不硬凑采集不到标"待核"，不为了凑数填假值标"待核"合规，硬凑违规

1.3 三道铁律（词条入库门禁）

铁律标准判定
找得到至少 2 个入口可达（搜索/场景/法条/案例）达不到不入库
看得懂标题 3 秒懂、一句话答案 ≤30 字、核心要点每条 ≤20 字达不到不入库
用得上含可执行动作或可引用依据，不是知识科普达不到不入库

二统一数据模型：双层结构

知识底座不是"只有词条"的单层锅。按知识形态分两层，各管各的、互相打通——这是解决"碎片塞不进词条库"的根本。

L1 · 词条层（规则/案例/政策/定义）

  • 回答"怎么办、是什么、有什么风险"——静态、可推理、问答型
  • 现有主库 entries_5000.json · 6968 条（OWN/PRE/CAR/LIV/P2/P3/CASE/POL/DEC/RNT/TRX…）。涨量靠新规则与案例，不靠硬塞动态数据。

⇅ 打通机制： 词条通过 dataRef 字段引用 L2 数据集（如 dataRef: DS-MKT-001）。消费端运行时"规则查 L1、出数查 L2"——决策引擎要讲理时读词条，要出数时打数据集，各取所长，互不污染。

L2 · 数据集层（真源动态数据）

  • 回答"现在值多少、通勤多久、哪个板块"——动态、结构化、可查询
  • 楼盘 / 市场行情 / 通勤测算 / 学区 / 绿化率 / 案例素材。按数据集登记（见第四节），绑定来源 + asOf，月度更新。

五采集生产流程（7 步闭环）

所有数据生产必须走完 7 步，缺一步不算完成。品控复核贯穿第 5 步，形成 采集 → 入库 → 品控 → 消费 全程闭环。

步骤动作要点
STEP 1 立项明确采集方向/范围/颗粒度登记数据集编号与口径（dsDef 先行）
STEP 2 采集按真源采集数值绑 source_url + asOf，多源冲突并列标注
STEP 3 格式化转统一字段契约L1 用 3.1/3.2，L2 用 4.2，旧字段名作废
STEP 4 自检3 轮自检 0 错误字段齐/来源可查/时效达标/无编造
STEP 5 送审提交小眼镜核验+ 独立 API 抽验（数值类如高德/官方口径）+ 品控复核（小酒窝儿）
STEP 6 入库L1 词条并入 entries 主库L2 数据集登记入数据字典，随版本管理
STEP 7 复采/版本L2 增量留史、全量出数重采先留历史快照；版本号与 asOf 强制绑定（记录版本号+数据截止日，v1.2 升级为强制措辞），禁止静默覆盖

入库前提： 未完成第 5 步核验的数据，一律标"待核"，不得进入任何对外/消费端输出。核验通过才可升"已核验"。

六质量门槛

6.1 权威分级（统一双轨制）

等级trustLevel来源类型入库要求
A≥ 0.85法律条文/司法解释/政府文件/官方数据标注发布机关+文号+日期，可直接引用
B0.75-0.85行业协会/权威机构/主流媒体/学术论文需标注"交叉验证"
C0.65-0.75行业报告/一般媒体必须双源验证才可入权威引用
<C< 0.65个人经验/自媒体/论坛不入库；或仅作"示意"并明确标注

双轨一致性硬校验： authority 与 trustLevel 必须落在对应区间（A≥0.85 / B 0.75-0.85 / C 0.65-0.75 / <C 0.65）。出现越界（如 authority=B 却 trustLevel=0.9）：以 authority 为准，整批退回修正后重审。验收表同步执行（见第八节）。

七消费端降级规则

知识库的"生产力"最终体现在消费端输出。规则：宁可"示意"，不出无依据硬数。

情形处理
数值无 source_url不渲染权威数值卡，降级"示意"
dataRef / caseRef 未补齐按"示意"执行，不出权威硬数
demo / 内部参考明确标注"示意"，不进正式输出
多源口径冲突并列标注，不合并取单值
数据已过期标注 asOf，禁止当现价引用
数据集未核验（status=待核）禁止进消费端权威引用

升级闭环（示意 → 已核验）： 降级不是终点：补齐缺失字段 → 重新送审 → 独立抽验通过 → 升"已核验"进入权威引用。双向闭环，数据不因一次缺失永久降级。

当前落地口径（已核实）： 6968 库中真实内容 dataRef 仅 19.1%、caseRef 仅 13.3%——按本标准，这些词条在消费端一律降级"示意"，不输出权威数值卡，待补齐后再升级。

九数据合规与安全

标准不只管"对不对"，还要管"能不能碰"。数据采集、存储、生产、消费全链路设防，隐私与敏感数据零容忍。

9.1 隐私红线（一票否决第 4 项）

零容忍任何含个人可识别信息（PII）的数据——姓名+联系方式、身份证号、精确门牌、车牌、人脸、家庭资产明细、家庭关系等——一律不得入库，无例外。谁碰谁违规，整批退回并追责到负责人。
