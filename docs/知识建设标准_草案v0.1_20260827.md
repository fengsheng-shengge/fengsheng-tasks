# 北京居住情报 · 知识/数据建设标准（草案 v0.1）

> 提案人：小马丫（知识采集）
> 评审对象：风声数字员工全员（小鱼儿总指挥 / 小眼镜监察官·知识图谱 / 小扣子代码 / 小豆子产品 / 小酒窝儿品控 / 小叮当增长官）
> 日期：2026-08-27
> 定位：**草案，不取任何单一个人经验为"唯一正确"**；待全员各自从职责视角评审、增补、修订后，收敛为全员共同认同的 v1.0 并作为知识底座统一底盘。

## 0. 为什么需要这份标准

- 现状问题：各采集轮次已在持续产出（市场数据库 v0.3→v1.4，附表 1~25），但字段口径、粒度、质量标记主要依赖采集者与提案人经验，**缺乏全员共同认同的"地基"**。
- 直接后果：知识底座的厚度、广度、规模无法度量；生产端调用率不高、价值未充分发挥。
- 目标：用一套**全员可执行、可校验、可扩展**的标准，把"经验"变为"共识"，让知识库可衡量、可持续、高调用。

## 1. 总则（四条铁律，全员共同遵守）

1. **可溯源**：一切数据绑定 source_url + asOf（数据时点）+ 采集日。
2. **不编造**：无公开值一律标「待补充」；无法核验标「待核」；严禁硬凑。
3. **多口径并列**：同一指标存在口径分叉时，并列标注来源，不取单一来源冒充权威。
4. **共建演化**：本标准本身按"提案→评审→锁定→版本化"演进，任何成员可提出修订。

## 2. 知识底座分层模型（四层）

| 层 | 名称 | 职责 | 核心字段 |
|---|---|---|---|
| L0 | 元数据层 | 记录数据来源、时点、可信度 | asOf / source_url / 采集日 / 来源级别 / 可信度标记 / 更新周期 |
| L1 | 指标层 | 统一指标定义、口径、单位 | 指标名 / 口径 / 单位 / 统计周期 / 环比同比 |
| L2 | 维度层 | 统一切片维度 | 行政区 / 板块 / 商圈 / 楼盘 / 小区 / 业态 / 面积段 / 价位段 |
| L3 | 质量层 | 统一质量状态标记 | 已核验 / 待核 / 待补充 / 多口径并列 / 推论(标注假设) |

## 4. 核心指标口径字典（L1 提案——重点评审项）

> 以下指标多次出现口径分叉，**需全员对齐"默认口径 + 并列规则"**：

| 指标 | 含义 | 已发现口径分叉 | 提案默认口径建议 |
|---|---|---|---|
| 二手成交(套) | 网签成交套数 | 住宅口径 vs 全口径 | 同时给住宅+全口径，标注 |
| 新房网签(套) | 商品住宅成交 | 住建委 vs 房天下 vs 克而瑞 | 多源并列标注，不合并 |
| 挂牌量 | 在售挂牌量 | 大中介前台(11.7万) vs 全量(14.03万) vs 住建委可比口径 | 标注口径：前台/全量/官方 |
| 挂牌均价 | 挂牌价格水平 | 房天下(5.4万) vs 58/安居客(3.7万) 差1.5-1.7万 | 多源并列，标注算法差异（成交加权/挂牌） |

## 5. 维度层约定（L2 提案）

- 行政区：北京 16 区 + 经开区（顺义、昌平等全 16 区覆盖）。
- 板块/商圈：以"贝壳/链家板块划分"为坐标主轴，其余来源映射对齐。
- 楼盘/小区：统一以备案名(地名办)为准，别名/推广名并列标注（如 中建·臻源府=臻源佳苑，实属延庆）。
- 粒度推进方向：宏观(全市)→分区→板块/商圈→楼盘→小区→逐套成交（P0-2 新房个人房源、P1-2 贝壳/链家逐套底档待补）。

## 6. 质量守则（L3 提案）

- 已核验：官方来源或双源一致 → 正常入库。
- 待核：单一低可信来源或平台自表述（如 "北京十一系"学校）→ 标「待核」，不得当定论。
- 待补充：明确缺失 → 标「待补充」，进待办清单。
- 多口径并列：分区均价等分歧大时，≥2 来源并列呈现。
- 禁止红字：凡"官方不公开/不存在"（如楼栋级划片红线）→ 记录"已核实不存在"，不再重复检索。

## 7. 版本与变更管理（提案）

- 数据版本：主库持续 v1.x 递增，附表 +1。
- 标准版本：本草案 v0.1 → 评审后 v0.2（合入全员意见）→ 全员确认 v1.0 锁定 → 后续修订走 RFC（变更说明+全员评审）。
- 事事留痕：每轮落盘+飞书回执 message_id 存档，可回溯。

## 8. 请全员评审的对齐项（重点清单）

1. L0 元数据字段：是否齐全？是否需要增加「用途标签/调用场景」「数据生命周期/存档」字段？
2. L1 口径字典：哪些指标需要收敛为唯一默认口径？哪些必须长期多源并列？
3. L2 维度：粒度推进顺序是否认可？是否需要按"生产端实际调用"反向定优先级？
4. 质量标记分级：是否认可"已核验/待核/待补充/多口径并列"五态？销售端最看重哪级？
5. 与知识供应链 v2.0（采集→入库→品控→消费）如何衔接：本标准的 L0-L3 是否为各环节通用？
