# 居住服务数据字典 v2.0 设计文档

> 更新日期：2026-08-04
> 版本：v2.0（场景驱动重构版）
> 变更说明：v1.0的60条宏观数据降级为"行业背景数据"层，新建"作业参考数据"层，按9个作业场景组织

## 一、设计原则

### 核心原则：场景驱动，经纪人能用

数据字典不是行业研究报告，而是经纪人的**作业弹药库**。每条数据必须回答两个问题：
1. **经纪人在什么场景下会用到这条数据？**
2. **怎么用？**（brokerUsage字段）

### 三不原则
- **不收录经纪人用不上的宏观数据**（如"全国物业管理行业规模7892亿元"→降级到行业背景层）
- **不收录没有具体数值的模糊描述**（如"市场将持续回暖"→不收录）
- **不收录来源不可靠的数据**（自媒体无出处的→不收录）

### 来源分级
| 级别 | 类型 | 示例 | 占比 |
|------|------|------|------|
| A级 | 政府/官方机构 | 住建委、公积金中心、统计局 | ~45% |
| B级 | 权威研究机构 | 中指研究院、克而瑞、国信证券 | ~25% |
| C级 | 头部企业数据 | 链家研究院、贝壳研究院、我爱我家 | ~20% |
| D级 | 平台/媒体 | 58同城、吉屋网、搜狐财经 | ~10% |

## 三、数据字段说明

```json
{
  "id": "SCN-{场景缩写}-{序号}",      // 如 SCN-CUS-001
  "scenario": "客户解码",               // 9个场景之一
  "indicator": "指标名称",
  "value": "数值",
  "unit": "单位",
  "year": "数据年份",
  "region": "地区（城市/区域）",
  "source": {
    "name": "来源名称",
    "type": "government/research/enterprise/platform/media/industry",
    "url": "来源URL",
    "publishDate": "发布日期"
  },
  "brokerUsage": "经纪人怎么用这条数据（核心字段）",
  "tags": ["标签1", "标签2"]
}
```

## 五、与v1.0的关系

| 维度 | v1.0 | v2.0 |
|------|------|------|
| 组织方式 | 8大分类（市场规模/供需/价格/人口/企业/政策/满意度） | 9个作业场景 |
| 数据用途 | 行业概览展示 | 经纪人作业参考 |
| brokerUsage | 无 | 每条必填 |
| 条数 | 60 | 76 |
| 来源 | 以研究报告为主 | 政府源占比45% |
| 定位 | "行业报告级"宏观数据 | "作业参考级"可用数据 |

v1.0的60条数据保留在 `data_dictionary_v1.0.json` 中，作为"行业背景数据"层，用于产品行业概览页面展示。

## 六、产品映射

### 网页端
- 行业概览页：展示v1.0宏观数据（市场规模/趋势/政策）
- 经纪人工具页：展示v2.0场景数据，按9场景分类导航
- 房源详情页：自动关联同区域的价格评估/风险识别数据

### 小程序端
- 场景卡片：每个场景一张卡片，3秒看到关键数据
- 谈判助手：签约谈判场景数据可直接调出
- 验房清单：交房验房场景数据做成检查清单
