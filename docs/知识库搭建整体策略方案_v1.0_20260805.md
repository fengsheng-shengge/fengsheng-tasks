## 一、一句话说清楚

**风声知识库是居住服务者的专业基础设施，由5417条结构化词条构成三层体系（数据→分类→场景），通过自进化机制持续产出和更新，最终让经纪人在任何见面场景下"打开就用、掏出来就有说服力"。**

---

## 二、为什么建、建给谁

### 2.1 问题

经纪人的专业能力取决于"记住了多少、能不能在客户面前说出来"。但行业现状是：
- 法规政策散落在各处，没有结构化整理
- 经纪人培训靠人传人，知识不沉淀
- 遇到客户追问，没有即查即用的专业弹药
- AI工具缺乏高质量知识数据源，问答不准

### 2.2 目标用户

| 用户 | 核心场景 | 知识库提供什么 |
|------|---------|--------------|
| **房产经纪人** | 客户见面全流程 | 法条、话术、工具卡、案例、风险提示 |
| **小程序用户** | 搜索/浏览专业内容 | 词条详情页、场景导航、FABE卡片 |
| **AI引擎**（小豆子） | 按场景调取知识 | 结构化数据+三维标签+场景映射 |
| **生哥** | 产品决策 | 知识覆盖率、质量指标、缺口分析 |

当前P0聚焦：**房产经纪人**（最高频、最刚需）

## 三、三层架构

```
┌─────────────────────────────────────────────────┐
│  第三层：场景驱动映射（怎么用）                      │
│  4条业务线 × 34个见面场景                          │
│  → 经纪人在什么场景调什么知识                       │
├─────────────────────────────────────────────────┤
│  第二层：知识分类体系（怎么找）                      │
│  8域 × 32子域 × 236知识单元                       │
│  → 知识按专业域组织，可检索可导航                   │
├─────────────────────────────────────────────────┤
│  第一层：数据结构（长什么样）                        │
│  5417条词条 × 35字段（22核心+5扩展+8实验）          │
│  → 每条词条是一个结构化知识单元                     │
└─────────────────────────────────────────────────┘
```

### 3.1 第一层：数据结构

每条词条35个字段，分三层：

| 层级 | 字段数 | 核心字段 | 作用 |
|------|--------|---------|------|
| **核心层** | 22 | id/domain/name/alias/detail/ola/cp/legalRef/dataRef/caseRef/consumerQ/consumerBenefit/entryType/priority/tags/severity/lastVerified/relatedEntries/source/dataSource/sceneDomain/subScene | 每条必有，定义"是什么、怎么说、依据什么、给谁用" |
| **扩展层** | 5 | ownerQ/ownerBenefit/ownerCard/caveat/toolType | 按条件填充，业主视角+风险提示+工具类型 |
| **实验层** | 8 | depth/brokerNote/posSpeech/negSpeech/caseIds/lawLayer/sceneId/fdeChain | FDE深度词条专用，部分转正中 |

**信息密度三层**：
- `ola`（一句话答，30字以内）→ 电梯话术
- `cp`（核心要点，3-6条bullet）→ 面谈要点
- `detail`（详细解答，200-500字）→ 深度咨询

**质量三支柱**：每条词条挂三个依据维度
- `legalRef` → 法律依据（法条名+条文号，已100%覆盖+法条真实性验证）
- `dataRef` → 数据支撑（引用数据字典76条）
- `caseRef` → 案例佐证（引用案例库）

**三维标签**（引擎调度核心索引）：
- `clientType` → 给谁用（buyer/seller/landlord/agent/tenant/owner）
- `stage` → 什么时候用（pre/mid/post/all）
- `layer` → 什么深度（dao道/fa法/shu术/qi器）
- `meetingPhase` → 见面哪个环节（见前/见中/见后）

> 字段设计规格书：`fengsheng-tasks/docs/字段设计规格书_v1.0_20260805.md`

| 域 | 名称 | 子域 | 词条数 | 覆盖度 |
|----|------|------|--------|--------|
| A | 法规政策 | A1不动产法律/A2调控政策/A3税费法规/A4租赁法规 | ~1226 | ✅ 充分 |
| B | 金融贷款 | B1商贷/B2公积金/B3征信额度/B4税务筹划 | ~500 | ✅ 充分 |
| C | 学区教育 | C1学区政策/C2学校评估/C3教育规划 | 60 | ✅ Phase2已补 |
| D | 交易流程 | D1签约/D2资金监管/D3过户交房/D4售后纠纷 | ~1132 | ✅ 最强域 |
| E | 商圈配套 | E1交通/E2生活配套/E3产业规划/E4区域发展 | ~400 | ✅ 充分 |
| F | 房屋评估 | F1户型/F2建筑品质/F3市场估值/F4物业管理 | ~500 | ✅ 充分 |
| G | 空间美学 | G1空间规划/G2装修风格/G3材料工艺/G4软装搭配 | ~400 | ✅ 充分 |
| H | 资产管理 | H1租赁托管/H2整装翻新/H3投资分析/H4资产配置 | ~1800 | ✅ 充分（含OWN域） |

每个子域下拆分为知识单元（共236个），每个知识单元关联多条词条。

> 全域重构文档：`fengsheng-tasks/docs/V3.0.15_知识库全域分类重构_20260804.md`

### 3.3 第三层：场景驱动映射

4条业务线 × 34个见面场景：

| 业务线 | 场景数 | 客户类型 | 核心场景 |
|--------|--------|---------|---------|
| 购房线 | 9 | 买房客户 | 首次接触→需求深挖→带看→委托→议价→签约→过户→售后→装修 |
| 租住线 | 8 | 租房客户 | 首次接触→匹配→带看→委托→签约→入住→租期管理→退租续租 |
| 业主出售线 | 9 | 出售业主 | 咨询→评估→委托→包装→看房→议价→签约→过户→资产优化 |
| 房东出租线 | 8 | 出租业主 | 委托→评估→翻新→托管→租客匹配→签约→租期管理→续约退租 |

每个场景挂接知识单元，经纪人按"我在服务谁→走到哪一步"调取知识。

## 四、数据流与协作链路

### 4.1 生产链路（自进化自循环）

```
巡采系统（每日自动）
    ↓ 发现新法规/新动态/新方法论
小眼镜（生产）
    ↓ 词条生产→3轮自检→quality_checker校验→0错误入库
小酒窝儿（审核）
    ↓ 六帽检查→法条真实性抽验→合规检
小鱼儿（复核+部署）
    ↓ 三端同步→GitHub+坚果云+小程序
小豆子+小扣子（产品落地）
    ↓ 引擎接入→API开发→前端呈现
```

### 4.2 三端同步机制

| 端 | 文件 | 路径 | 同步频率 |
|----|------|------|---------|
| GitHub | entries.json / entries_5000.json | `fengsheng-tasks/data/` | 每次commit + 每日08:00自动 |
| 坚果云 | entries_latest.json / entries_5000.json | `/风声知识底座备份/` | 每日08:00自动（push_entries_sync.py） |
| 小程序 | entries_slim.js（704条精简版） | `fs-mini-program/src/.../data/` | 按需更新 |

**唯一真源**：`entries_5000.json`（5417条），所有同步以此为准。

### 4.3 知识反哺系统

4条巡采线每日09:00自动执行：

| 巡采线 | 追踪范围 | 反哺路径 |
|--------|---------|---------|
| 政策法规 | 限购/公积金/税费/民法典/经纪监管 | 新法规→标记受影响词条→更新caveat |
| 行业竞品 | 贝壳/经纪人工具/SaaS/融资 | 竞品动作→标记产品影响→推#184/#185 |
| AI方法论 | Agent落地/RAG/FDE/LTRUST | 新方法论→评估入库价值→产出dao/fa层 |
| 硅谷AI动态 | AI技术趋势/产品发布/融资 | 技术方案→影响产品架构决策 |

反哺改动走审核链路：巡采→小眼镜改动+校验→小酒窝儿→小鱼儿→部署，不得跳审。

### 4.4 质量保障体系

| 环节 | 工具/方法 | 标准 |
|------|----------|------|
| 生产自检 | quality_checker.py（21字段全量校验） | 0错误0警告 |
| 法条验证 | 法条真实性系统性验证 | 每条legalRef可溯源 |
| 审核环节 | 小酒窝儿六帽检查 | 白/黄/黑/红/绿/蓝六视角 |
| 合规门禁 | 涉法内容必过合规检 | 法律合规100% |
| 时效核查 | 政策类每季度核查 | lastVerified+expiryCycle |

## 七、知识库的四个层次

不只是词条数据库。风声知识库有四个层次，每层服务不同目标：

| 层次 | 内容 | 数量 | 服务谁 |
|------|------|------|--------|
| **长期记忆** | entries_5000.json（结构化词条） | 5417条 | 小程序搜索/AI引擎/经纪人查询 |
| **工作记忆** | 工具卡（broker_toolkit） | 68条→扩展中 | 经纪人见面时即查即用 |
| **经验记忆** | 案例库（case_library） | 17条→扩展中 | 客户质疑时拿出判例佐证 |
| **情境记忆** | 场景卡片（scene_cards） | 4条→扩展中 | 小程序首页/MOT策展 |

四层联动：任何一层缺失，终端就降级为"展示层"而非"记忆层"。
