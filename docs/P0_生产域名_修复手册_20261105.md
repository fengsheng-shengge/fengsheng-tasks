## 三、只剩一条人工动作（二选一）

### 路线 A：Dashboard 手加一条记录（最快，30 秒）

1. 打开 Cloudflare Dashboard → Zone **fengsheng.tech** → **DNS** → Records → **Add record**
2. 填：

   | 字段 | 值 |
   |---|---|
   | Type | `CNAME` |
   | Name | `fengsheng.tech` |
   | Target | `fengsheng-ee9.pages.dev` |
   | Proxy status | **Proxied**（橙云） |
   | TTL | Auto |

3. 保存后等 1～5 分钟生效

> 注意：必须是 **CNAME 指向 `fengsheng-ee9.pages.dev`**。
> 如果 Cloudflare 提示与已有 A 记录冲突，说明有残留记录，先删掉再按上面加。

### 路线 B：给一个带 DNS 写权限的 token，全自动修

1. Cloudflare Dashboard → My Profile → API Tokens → Create Token → **Edit zone DNS** 模板
   - Permissions：`Zone → DNS → Edit` + `Zone → Zone → Read`
   - Zone Resources：`Include → Specific zone → fengsheng.tech`
2. 把生成的 token 存成仓库 secret：
   `Settings → Secrets and variables → Actions → New repository secret`
   - Name：`CLOUDFLARE_DNS_TOKEN`
   - Value：刚生成的 token
3. 跑工作流 **🌐 修复生产域名绑定与 DNS**（`fix-prod-domain.yml`）
   - `apply = true`
   - `hostname = fengsheng.tech`
4. 脚本会自动建 CNAME 并做三轮可达性探测

跑 **🌐 修复生产域名绑定与 DNS**（apply=false）做 dry-run，或者直接：


再跑 **🧪 代理 Worker 端到端自检**（`verify-proxy-worker.yml`）做全量比对。

## 五、DNS 落地之后还要做的事（按顺序）

1. **微信公众平台 → 开发管理 → 开发设置 → 服务器域名**
   - 把 `https://fengsheng.tech` 同时加入 **request 合法域名** 和 **downloadFile 合法域名**
   - 原来只配 request 是不够的，小程序码下载走的是 downloadFile
2. **小程序真机埋点复核**：真机跑一遍，确认 `POST /api/events` 落库
3. **兜底域名的取舍**：
   - 兜底域 `fengsheng-ee9.pages.dev` **没有 ICP 备案**
   - 所以：真机调试 / 体验版（勾选「不校验合法域名」）可用，**正式发布版只能用已备案的 fengsheng.tech**
   - 也就是说，**备案这件事仍然是正式发布的硬门槛**，与 DNS 修复并行推进

## 六、已铺好的兜底链路（DNS 一落地就自动生效）

```
fengsheng.tech
   └─ Worker 路由  fengsheng.tech/*  →  fengsheng-proxy
        └─ 转发到  https://fengsheng-ee9.pages.dev   （Pages 真身，D1/KV 绑定都在那边）
             └─ _worker.js  →  D1 / KV / 缓存
```

验证结果（run 42026065403）：代理的 `/`、`/api/health`、`/api/stats/summary`、`/api/stats/pages`
与 Pages 兜底域**逐字节一致**（归一化易变字段后 sha 相同）。

- 代理 Worker 脚本：`fengsheng-proxy`
- 入口：`https://fengsheng-proxy.yu-er.workers.dev`
- 兼容标志：`global_fetch_strictly_public`（否则会报 error 1042：Worker 试图 fetch 同 zone 的另一个 Worker）
- 路由：还有一条账户里原本就有的 `hwj.fengsheng.tech/* → small-sky-e81chwj-proxy`

> 如果后面想让 Pages 直出（少一跳），删掉 `fengsheng.tech/*` 这条 Worker 路由和 `fengsheng-proxy` 脚本即可，
> Pages 自定义域名本身已经绑好，会直接接管。
