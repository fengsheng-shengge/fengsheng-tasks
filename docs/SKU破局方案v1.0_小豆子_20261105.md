**结论**：SKU 卡了 22 天，**不是内容不够，是「切法」与「验证口径」两样东西没人定**。内容侧有 6143 条原料、5844 条已带 C 端问答对；商业化侧要到 2027 Q2 才开闸；而各处已有的「定价」讨论（导师连通用 ¥0.99/¥9.9、主站付费内容工单）**彼此没有同一 SKU 口径**。两头一夹、中间又没定义，SKU 就会一直挂在「立项」上等一个不会来的日期。

**因此本方案的定义式破局**：

> **年底的 SKU = 要验证的「价值单元」，不是要卖的「商品单元」。**
> 一个 SKU = 一个普通门店愿意为一个结果付费的场景 + 支撑它的问答对集合 + 风险分级 + 交付形态。
> 收费行为、金额、支付入口全部推到 2027 Q2 商业化拍板；年底用**行为代理指标**验证价值假设，不假装在收费。

## 一、范围（What）

### 1.1 切法原则

按**交易生命周期 + 门店角色**切，不按 `entryType` 切。
理由：按 entryType 切出来是「PROC 1301 条 / LAW 1226 条」这种内部结构，对门店没有购买意义；按场景切，门店看到的是「我要解决的那件事」。

### 1.2 五个候选场景包（v1.0 范围）

数据来源：`data/entries.json` 权威源（2026-11-05 A 类更名清扫后，6143 条）。条目数按域精确统计。

| --- | --- | --- | --- | --- | --- |
| **S1** | 签约前 · 带看与谈判包 | 签约前、带看服务、谈判斡旋、业主、业主侧 | **1568** | 1568 / 1568 | STD 306、PROC 302、RISK 274、LAW 259、CASE 193、POL 146、TERM 88 |
| **S2** | 签约中 · 定金与违约风险包 | 签约中、签约前 | **1526** | 1526 / 1526 | STD 293、LAW 292、PROC 280、RISK 220、POL 204、TERM 135、CASE 102 |

- 五包并集去重 **5253 / 6143 = 85.5%**
- S1–S4 的 C 端问答对 **100% 覆盖**；S5 未满（ABIS/SUM/JOB/CERT/QUIZ 为内部管理条目，本就不面向 C 端，属正确形态）

### 1.3 SKU 的最小单元定义

```
SKU = 场景（1 个门店可感知的结果）
    + 问答对集合（consumerQ / consumerBenefit，原料已齐）
    + 风险分级（severity：hard / medium / soft，直接决定交付形态与优先级）
    + 交付形态（话术卡 / 清单 / 剧本 / 测评）
```

**不逐条 SKU 化**：6143 条逐条切等于没切，粒度过细反而无法验证。

### 1.4 明确在范围内 / 范围外

| | 内容 |
| --- | --- |
| **范围内** | ① 5 个场景包的定义与边界 ② 各包交付形态设计 ③ 定价**假设**（价值锚点 + 相对结构）④ 最小验证路径与代理指标 ⑤ 小程序侧承接口径（我的 lane） |
| **范围外** | ① 主站代码实现（小扣子 lane）② 支付/价格展示/付费入口 ③ 具体金额 ④ 逐条 SKU 化 ⑤ 成交数字承诺 |

## 二、定价假设（What for price）

> **硬约束**：年底不产生任何收费行为；本节给的是**假设**，不是价格，不是承诺。金额化留到 2027 Q2 商业化拍板。

### 2.1 为什么年底不能给价

- 给价 = 默认 SKU 已经成立 = 跳过验证。而 O-验证线的口径是**先有 6 家门店在用，再谈反哺**。
- 付费入口拍板前 0 处（KR4.1）。方案里出现价格，落地时就会有人去挂入口 —— 这正是要防的越界。

### 2.2 定价假设的三个锚点（替代「拍脑袋定价」）

| 锚点 | 含义 | 本方案可用的现成口径 |
| --- | --- | --- |
| **A. 替代方案成本** | 门店不用这套东西，找中介/自己跑腿要花多少 | 6 店回访表采集（人工填，非系统） |
| **B. 错误代价** | 一条 `severity=hard` 的风险踩中的赔付 / 违约成本 | 底座已有 `severity` 三色分级：**hard 2467 / medium 2005 / soft 1393 / low 5** |
| **C. 人工工时** | 新人上手节省多少工时 | 对接小豆子 KR1.2「店东 **30 分钟**内独立完成开通→出第一单」的可复跑计时输出 |

### 2.3 相对价格结构（只给结构，不给数）

| SKU | 相对档位 | 理由（可证伪，不是形容词） |
| --- | --- | --- |
| S5 新人上手 | **低** | 一次性 / 订阅型；错误代价低，但频次高 → 适合低门槛长期黏住 |
| S3 交房入住过渡 | 中 | 频次中等，错误代价中；但 LAW 501 条占其 34.4%，法规密度高 |
| S1 带看谈判 | 中高 | 直接对客、频次高；STD 306 条为标准动作集，可复用性强 |
| S4 租客管理 | 中高 | CASE 226 条占 35.8%，是**已发生过的真实纠纷**，最贴近门店日常痛感 |
| S2 定金违约风险 | **最高** | 一次性、错一次代价最大、且是「成交前最后一道闸」；RISK 220 + LAW 292 是全部包里最硬的组合 |

**档位只表达相对关系**。绝对金额需 2027 Q2 结合 A/B/C 三锚点实测后另行拍板。

### 2.4 可证伪的价值假设（这一条替代「定价」在年底的作用）

> **H-SKU**：若 6 家验证门店中 **≥4 家**在连续 **4 周**内使用某场景包，且该包覆盖其对客应答的 **≥30%**，则该包的价值假设进入「成立候选」，可进入 2027 Q2 商业化定价候选池。

判定用**行为**不用**支付意愿**——因为年底没有支付行为可用。这条假设要么被 6 店证伪，要么被证实，**不接受「大家觉得挺有价值」这类不可证伪的结论**。
