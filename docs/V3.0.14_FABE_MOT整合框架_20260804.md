# V3.0.14 FABE × MOT 整合框架设计

> 2026-08-04 · 知识底座深度化 + 服务流程节奏化

## 一、设计缘起

用户提出两个升级方向：

1. **知识底座多维度**：词条不仅给"说明"，还应包含理论依据、数据佐证、案例呈现——参考 FABE 销售方法论（Feature功能 / Advantage优势 / Benefit利益 / Evidence佐证）
2. **服务流程 MOT 化**：经纪人与客户的服务模式按 MOT（Moment of Truth）组织——探索 / 提议 / 行动 / 确认

**核心理念**：FABE 给知识"深度"（每条词条的四维结构），MOT 给流程"节奏"（见面过程的四阶段）。两者正交，构成"内容深度 × 交互节奏"双维矩阵。

## 二、FABE 字段映射

### 2.1 现有字段 → FABE 映射

| FABE | 含义 | 现有字段 | 状态 | 说明 |
|------|------|----------|------|------|
| **F** Feature | 功能/词条说明 | `name` + `detail` | ✅ 已有 | 词条名称 + 详细说明，回答"这是什么" |
| **A** Advantage | 优势/亮点 | `ola` + `cp` | ✅ 已有 | 一句话话术 + 核心要点，回答"为什么重要/有什么不同" |
| **B** Benefit | 利益/客户价值 | `consumerBenefit` | ✅ 已有 | 对客户的具体利益，回答"客户得到什么好处" |
| **E** Evidence | 佐证 | `legalRef` | ⚠️ 部分 | 仅法规依据，缺数据佐证和案例呈现 |

### 2.2 E 维度扩展（新增 2 字段）

| 子字段 | 含义 | 示例 | 来源 |
|--------|------|------|------|
| `legalRef` | 法规/政策依据 | 《民法典》第577条 | ✅ 已有（634条中37条含真实法源） |
| `dataRef` | 数据/市场佐证 | 同板块均价对比、成交量趋势、租金回报率 | ✚ 新增，需小眼镜补充 |
| `caseRef` | 案例/判例呈现 | 真实交易案例、法院判例、行业通案 | ✚ 新增，需小眼镜补充 |

### 2.3 真实词条 FABE 展开（样本）

以 `PRE-NEED-018 换房改善怎么规划最划算` 为例：

```
F (功能)：
  换房改善怎么规划最划算
  改善换房分两种路径：先买后卖和先卖后买。先买后卖风险在于旧房滞销导致同时
  承担两套房贷；先卖后买风险在于过渡期无房住且房价可能上涨。

A (优势)：
  销冠话术：看首付充裕度和旧房好不好卖，同城市可退个税
  核心要点：
    ① 先买后卖担两份月供风险
    ② 先卖后买怕过渡期涨价
    ③ 首付充裕度决定路径选择
    ④ 同城市换购可退个税
    ⑤ 旧房流通性是关键变量

B (利益)：
  选对路径省利息省税费，不两头受压

E (佐证)：
  法规依据：《关于延续实施全年一次性奖金个人所得税政策的公告》
            （财政部 税务总局2023年）；换购住房个税退税政策延续至2027.12.31
  数据佐证：[待补充] 同城市换房个税退税金额测算案例
  案例呈现：[待补充] 先买后卖导致双月供压力的真实案例
```

### 2.4 引擎 say 输出结构升级

```javascript
// 升级前
say: [
  { title, point, detail, legalRef, hasLegal, entryId }
]

// 升级后（FABE 展开，向后兼容）
say: [
  {
    entryId,
    title,           // F: 词条名
    feature: {       // F: 功能说明
      summary: ola,  //   一句话
      detail: detail //   详细说明
    },
    advantage: {     // A: 优势/亮点
      points: cp     //   核心要点数组
    },
    benefit: {       // B: 客户利益
      text: consumerBenefit
    },
    evidence: {     // E: 三重佐证
      legalRef: legalRef || null,    //   法规依据
      dataRef: dataRef || null,      //   数据佐证（新增）
      caseRef: caseRef || null,      //   案例呈现（新增）
      hasAny: Boolean                //   是否有任何佐证
    }
  }
]
```

## 三、MOT 服务流程映射

### 3.1 现有 说/带/问/跟 → MOT 映射

| MOT 阶段 | 含义 | 现有结构 | 映射逻辑 |
|-----------|------|----------|----------|
| **M1 探索** Explore | 了解客户真实需求、顾虑、约束 | `ask` (问) | 问就是探索的工具——通过必问问题打开客户认知 |
| **M2 提议** Propose | 呈现知识方案、展示专业价值 | `say` (说) | 说就是提议的载体——用 FABE 结构呈现每条知识 |
| **M3 行动** Action | 现场执行：带看、测算、展示工具 | `bring` (带) | 带就是行动的物料——工具/数据/对比卡当面用 |
| **M4 确认** Confirm | 确认共识、设下步、持续跟进 | `followups` (跟) | 跟就是确认的延续——埋引子+持续关怀 |

### 3.2 MOT 输出结构

```javascript
// 引擎输出新增 mot 包装层（与 say/bring/ask/followups 并行，向后兼容）
mot: {
  explore: {
    label: '探索',
    goal: '了解客户真实需求、预算约束和决策顾虑',
    questions: ask,          // 复用现有 ask 数组
    prompts: [               // 场景化探索引导（从 SCENARIOS 配置读取）
      '您这次换房主要是因为什么？',
      '首付和月供大概能接受什么范围？'
    ]
  },
  propose: {
    label: '提议',
    goal: '用专业知识帮客户看清选择和利弊',
    items: say,              // 复用 say（FABE 结构）
    tool: recommendedTool    // 推荐呈现工具
  },
  action: {
    label: '行动',
    goal: '现场执行——带看/测算/对比/签约',
    tools: bring,            // 复用 bring
    steps: [                 // 场景化行动步骤（从 SCENARIOS 配置读取）
      '展示3套候选房源对比卡',
      '现场计算首付+月供+税费全口径'
    ]
  },
  confirm: {
    label: '确认',
    goal: '确认客户理解、锁定下一步、埋持续服务引子',
    followups: followups,    // 复用 followups
    checklist: [             // 场景化确认清单（从 SCENARIOS 配置读取）
      '客户已明确预算范围',
      '已约定下次带看时间'
    ]
  }
}
```

### 6.2 填充优先级

**Phase 1（V3.0.14）**：引擎结构升级

- E.dataRef / E.caseRef 缺失时显示"数据佐证待补充"，不编造
- MOT 包装层从现有 say/bring/ask/followups 自动组装 + 场景配置补充

**Phase 2（V3.0.15）**：词条 E 维度填充
- 小眼镜优先为 top 40 强相关词条补充 dataRef + caseRef
- 目标：E 维度覆盖率从 5.8% → 30%

**Phase 3（V3.0.16+）**：全量填充
- 634 条逐步补齐 E 三维
- 目标：E 维度覆盖率 → 60%+
