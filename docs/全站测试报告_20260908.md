## 三、用户互动 → 致命缺陷

### ❌ P0-1: AI 聊天助手完全不可用

**问题**：`toggleChat()` 和 `sendChat()` 函数未定义

**影响**：首页聊天按钮点击后，控制台报 `ReferenceError: toggleChat is not defined`，对话框不会弹出。用户无法与 AI 助手交互。

**根因**：`index.html` 中有完整的聊天 UI HTML（`#chatFab`、`#chatDialog`、`#chatInput`、`#chatSend`），但对应的 JS 交互逻辑从未被实现。后端 `_worker.js` 的 `/api/chat` 端点（代理 Coze API）已就绪，只是前端未连接。

**修复方案**：在 `index.html` 末尾添加 `toggleChat()` 和 `sendChat()` 函数，调用 `/api/chat` 端点。

### ❌ P0-2: 反馈评分组件完全不可用

**问题**：星星评分点击无响应，提交按钮永远 disabled

**影响**：用户看到评分 UI 但无法交互，反馈功能形同虚设。无法收集用户反馈意见。

**根因**：`index.html` 第 507-517 行有完整的反馈 UI（5 星 + 文本框 + 按钮），但没有任何 JS 代码：
- 绑定 `.fs-star` 的 `click` 事件（无法评分）
- 绑定 `#fs-fb-submit` 的点击事件（无法提交）
- 评分后启用提交按钮

**修复方案**：在 `index.html` 末尾添加反馈交互逻辑，评分后调用 `POST /api/event` 提交。

### ❌ P0-3: 数据埋点 `setupReplyForm` 监听不存在的元素

**问题**：`tracker.js` 第 248 行 `setupReplyForm()` 监听 `id="reply-form"` 的元素，但首页中没有这个元素。

**影响**：`reply_submit` 事件永远不会被触发，反馈提交数据无法被追踪。

**修复方案**：更新 `tracker.js` 中 `setupReplyForm()` 的监听目标为 `#fs-fb-submit`。

## 四、数据埋点 → 系统性缺陷

### ⚠️ P1-1: `tracker.js` 使用 `async` 加载（时序问题）

**问题**：所有页面通过 `<script src="/tracker.js" async>` 加载 tracker，`async` 属性意味着 tracker 可能在页面内联脚本执行完成之后才加载完毕。

**影响**：如果用户在内联脚本执行期间与页面交互（点击按钮、滚动等），这些交互事件可能不会被 tracker 捕获。`fsTrack()` 可能在调用时尚未定义。

**建议**：改为 `<script defer src="/tracker.js">` 或移除 `async`。

### ⚠️ P1-2: 点击埋点选择器过宽

**问题**：`tracker.js` 第 220-229 行 `setupAutoClick()` 监听所有 `A`、`BUTTON`、`[data-track]`、`[role]` 元素的点击事件。

**影响**：大量无关元素也被追踪，导致数据噪声大。同时 `aria-label` 作为点击标签可能导致隐私信息泄露（如用户输入内容）。

**建议**：限制为 `[data-track]` 和 `data-track="true"` 的显式埋点元素。

### ⚠️ P1-3: 反馈数据无独立分析入口

**问题**：反馈数据通过 `POST /api/event` 写入 D1 的 `events` 表，但管理看板中没有独立的反馈分析视图。

**影响**：无法查看用户反馈趋势、评分分布、反馈关键词等。

**建议**：在管理看板中增加反馈分析模块。
