## 〇、结论先行（一句话）

**V3.0 让风声从「信息展示工具」跨代升级为「见面指导工具」：经纪人开口前，工具基于真字典 + 这个客户的真实情况，秒出专属的"说/带/问/跟"方案，且每一条都有真实依据背书。**

这是从"经纪人自己翻词条硬想"到"有专业后盾替我准备"的质变——直接命中产品铁律最核心的痛：**「经纪人靠嘴、讲错丢信任；现有工具只展示不指导」**。

---

## 一、为什么这是"质的飞跃"（对比 V2.x）

| 维度 | V2.x（展示型） | V3.0（指导型） | 飞跃感 |
|------|---------------|---------------|--------|
| 核心价值 | 把真字典/方法论**展示**给经纪人看（知识页、策展包列表） | 把真字典/方法论**变成**经纪人的见面参谋 | 从"给我看"到"替我备" |
| 准备动作 | 经纪人自己读词条、自己拼方案 | 输入客户当下情况 → 秒出专属策展包 | 准备时长量级下降 |
| 信任来源 | 经纪人自己的专业积累 | 每条"说"都挂真实依据 legalRef | 讲错风险结构性降低 |
| 客户经营 | 客户档案靠录入 | 每次互动自动沉淀"认知复利" | 越用越懂客户，持续用 |

**飞跃的本质**：工具角色从「嘴的延伸（展示）」升级为「嘴的延伸 + 校准器 + 信任重建器 + 记忆点制造器」四位一体——这正是 7.23 定位终裁里定义的工具本质，V2.x 只实现了前半句，V3.0 补全后半句。

## 二、核心模块设计

### 模块一 · 智能策展生成（见面参谋）【P0 · 飞跃核心】

- **入口**：客户档案页 / 今日跟进 → 点「准备这次见面」
- **输入**：
  - 客户当前「人生双纵轴」节点（购5：首套→改善→教育→升级→适老 ／ 租4：起步→改善→家庭→品质，单选当前阶段）
  - 「住得好七维」关注点（物质安全/健康/便利/经济/舒适/美观/自在，可勾选或默认）
  - 一句自由诉求（如"想换改善型三房，预算800万，纠结学区"）
- **引擎**：基于真字典检索增强生成
  - 业务字典（570条：ola=销冠话术 / legalRef=真实依据 / cq=必问）
  - 人才字典（9岗×5维=45点，校准"经纪人该展现什么专业度"）
- **输出：结构化策展包**（严守产出物铁律：说/带/问3–5件事 + 见后跟进，NOT 词条列表）
  - **说**：3–5 条该客户该阶段该说的真实要点，每条附 `legalRef` 真实依据（可点开看原文）
  - **带**：该带看的房源类型 / 案例方向（关联知识页案例灵感）
  - **问**：该问的 `cq` 必问，用于探需求、验证决策信号
  - **见后跟进**：埋的引子 + 持续关怀点（统称"见后跟进/持续关怀"，禁用"钩子/策略/转化"等操纵词）
- **铁律遵守**：依据必映射字典，绝不编；输出校验——每条"说"必须能回链 legalRef，否则不展示。

### 模块二 · 客户认知复利图谱 【P1 · 持续使用引擎】

- **沉淀**：每次「准备见面」（记录的阶段/关注点）+ 「见后跟进」（记录的客户反馈/决策信号）自动累加到客户档案。
- **呈现**：客户档案下生成「认知卡」——已知偏好 / 暴露痛点 / 决策信号 / 阶段演进（时间线）。
- **反哺**：下次「准备这次见面」时，自动呈现"这个客户已知什么、还缺什么、这次该补什么"，让经纪人感觉客户越服务越懂。
- **这是护城河「沉淀复利」的真正落地**——客户数据留在经纪人侧（不收数据），越用越值钱。
- **数据诚实**：认知卡初始为空，靠真实互动涨，不送假数据（符合用户视角铁律①）。

### 模块三 · 三段式见面时间轴（仪式感升级） 【P1 · 体验润色】

- 策展包从纯列表 → 时间轴分镜：**见前准备**（看策展包）/ **见面执行**（说·带·问节奏提示）/ **见后跟进**（引子+关怀）。
- 降低经纪人"见面焦虑"，给清晰节奏，制造记忆点。

### 模块四 · 客户经营驾驶舱（远景） 【P2 · 一次委托终生服务】

- 多客户并行经营看板：基于认知复利，主动提醒"张三改善阶段信号出现、该推学区了""李四适老节点将至、该创造服务机会"。
- 是「一次委托终生服务」哲学的集中体现，让经纪人感觉"工具在替我经营客户"。
- 依赖模块二的数据积累，建议 V3.1 或 V4 落地。

## 三、铁律校验（逐项过）

| 铁律 | V3.0 遵守方式 |
|------|--------------|
| 虚拟支付规避 | 全功能免费；信任积分仍仅真实服务动作发放，不套任何购买/兑换/会员外壳；无 ¥价格/订阅/充值文案 |
| 用户视角最高优先 | 三问裁决：有用吗（替我备方案）／好用吗（秒出+时间轴）／会持续用吗（认知复利越用越值） |
| 数据诚实 | 认知卡初始空、靠真实互动涨；策展包依据必回链 legalRef，不编造数据 |
| 依据真实不幻觉 | LLM 检索增强（RAG），生成严格约束在真字典映射内；输出校验回链 |
| 禁用操纵词 | 对外统称"见后跟进/持续关怀"，禁用"钩子/策略/转化"；送审前 grep 0 命中 |
| 产出物铁律 | 策展包=说/带/问3–5件事+见后跟进，NOT 词条列表 |
| tabBar≤5 | 新增功能挂载在现有「策展」tab / 「客户档案」tab 内，不新增底部 tab |

## 四、六问（生哥铁律 · 必答）

1. **依据**：产品铁律「工具=嘴的延伸/校准器+信任重建器+记忆点制造器」；护城河「依据真不幻觉+沉淀复利」；7.23 定位终裁「见面策展工具，插入点见前+见后」；真字典底座（业务570+人才45）。
2. **设计原因**：V2.x 只展示不指导，经纪人仍需自己拼方案，核心痛"怎么讲才对、讲错丢信任"未被解决。把真字典变参谋，是从展示到指导的质变，补全工具本质的后半句。
3. **效果**：① 准备时长从"翻词条硬想"→"秒出专属方案"；② 讲错风险结构性降低（每条说挂真实依据）；③ 客户信任提升（专业背书可视化）；④ 持续使用（认知复利让越用越值）。
4. **解决谁的问题**：经纪人（用户）的"不知怎么讲/讲错丢信任/客户经营无方法"；间接解决客户"遇不专业经纪人"的痛；护城河"站经纪人给尊严不收数据"同步强化。
5. **方式**：LLM 作发动机（moat 已预留"LLM 可换发动机"），但生成内容用检索增强严格约束在真字典映射内（RAG + 输出回链校验），防幻觉；客户认知图谱用结构化字段累加（非生成）；小程序端经服务端代理调 LLM（密钥不下发前端）。
6. **验证**：① 用户视角三问走查（有用/好用/持续用）+ 真机截图；② 100 人验证线（9.1 前）实测：平均准备时长下降%、跟进率提升%；③ 虚拟支付扫描 src+dist 0 命中；④ 依据回链校验通过率 100%（每条说都有 legalRef）。

## 五、优先级建议（请生哥确认）

- **P0｜模块一 智能策展生成** —— 飞跃核心，单独上线即有质变，优先做。
- **P1｜模块二 客户认知复利图谱** —— 增强持续使用，紧接 P0（P0 产生的数据即其养料）。
- **P1｜模块三 三段式时间轴** —— 体验润色，成本低，可与 P1 并行。
- **P2｜模块四 经营驾驶舱** —— 远景，依赖模块二数据积累，V3.1/V4 再做。

> 建议 V3.0 先交付 P0+P1（策展引擎 + 认知复利），构成完整"指导型"体验闭环；模块三作为同版润色；模块四留待下个版本。

## 六、风险与约束

- **LLM 集成**：小程序端不能裸调大模型，需服务端/云函数代理（密钥保护）；或走现有 LLM 通道。属技术预研项，实现前需小扣子/马千行确认部署形态。
- **防幻觉硬约束**：检索增强 + 输出回链校验是必做项，否则违背"依据真不幻觉"铁律；建议生成后强制"每条说↔legalRef"绑定，缺失则不渲染该条。
- **资源/性能**：策展生成属非实时（见前准备），可异步；真机预览仍需人工（送审铁律）。
- **送审铁律不变**：虚拟支付扫描 0 命中、资源 ≤200K、wxss 禁中文类名等，V3.0 同样须过。
