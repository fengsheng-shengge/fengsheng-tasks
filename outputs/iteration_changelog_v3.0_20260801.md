## 一、本次迭代解决的核心问题

V2.7 的工具仍是「展示型」——把知识罗列给经纪人看，但经纪人靠嘴吃饭、讲错就丢信任，且现有工具不指导「这次见面该说什么/带什么/问什么」。V3.0 把工具升级为「指导型」见面策展器：把真实业务字典转化为每次客户接触可执行的策展包。

## 二、新增功能

| 模块 | 改动点 | 解决啥 | 做了啥 |
|------|--------|--------|--------|
| 策展引擎 | 新增 `package-curation/engine.js` | 经纪人见客户前不知道聊啥、带啥、问啥 | 确定性（无 LLM）检索增强：双纵轴(购5/租4)+七维(4+2+1)+自由诉求 → 说/带/问/跟 四类策展项，每项挂真实 `legalRef` |
| 策展准备页 | 新增 `package-curation/pages/curate-prep/index.vue`（分包非 tab 页） | 从零填表太重 | 客户档案一键带入预填 + 生成策展包 + 三段式时间轴（见前/见中/见后）+ 存入认知卡 |
| 客户认知复利卡 | `src/pages/clients/index.vue` 新增卡片 | 客户偏好散落、无积累 | 已知偏好/决策信号/关怀点，初始空、随真实见面动作沉淀（非积分外壳） |
| 策展入口 | `src/pages/curate/index.vue` 新增 CTA | 旧版入口无新版能力 | 新增「见面参谋（新版）」，旧版降级保留 |

## 三、优化改进

- **词典瘦身隔离**：570 词条精简至 `entries_slim.js`（333KB，545 条真实法源），移入分包，主包降至 1.5M（<2MB 红线）
- **幻觉边界（R2）**：仅真实法源挂「依据」徽标，25 条缺依据如实标「依据整理中」，引擎零编造
- **诚信报告（honesty）**：强相关阈值 score≥4，杜绝「匹配 467 条」式虚高（实测强相关 40 / 真实法源 37）
- **用户视角铁律**：产品面禁用「钩子/策略/转化」等操纵词，对外统称「见后跟进/持续关怀」（grep 0 命中）

## 七、送审合规自检（微信审核红线 · 2026-08-01 加固）

面向微信官方审核（非仅内部铁检）的红线逐项核验：

| 审核红线 | 结论 | 说明 / 处置 |
|---------|------|------------|
| 虚拟支付资质 | ✅ 不触发 | 功能码扫描 0 命中；信任积分仅由真实服务动作获得、不可购买/兑换；案例全部免费（无付费/积分解锁） |
| 诱导分享 | ✅ 不触发 | `earnTasks` 无 share 任务、`incShare` 未接线 → 无「分享得积分」激励；`open-type="share"` 仅为原生合法转发（把案例发给客户） |
| 绝对化用语 | ✅ 已修 | 「最佳案例库」→「精选案例库」（去"最/佳"等违禁超级词） |
| 功能完整性 | ✅ 已修 | 去掉「职业档案（模拟）」等占位信号 → 改为「· 后续版本开放」，避免审核判"功能不完整" |
| 隐私保护 | 🟢 已补+需后台 | App 内新增隐私政策页（本地数据不上传/不撮合说明）；**MP 后台「隐私保护指引」需小鱼儿人工配置** |
| 资源/构建规范 | ✅ 全过 | 单文件资源均 ≤200K；wxss 无中文类选择器；wxml 无遗留 HTML 标签；分包 712K/主包 1.5M 均 <2MB |
| 后端依赖 | ✅ 无阻断 | `login()` 运行时未被调用，核心功能（知识/策展/客户档案）纯本地，审核员可全量试用，无 404/白屏风险 |
| 类目资质 / 备案 / 主体 | ⚠️ 需人工 | 房产中介类目资质、小程序 ICP 备案、企业主体认证 → 由小鱼儿在 MP 后台确认（代码无法代配） |

**结论**：代码侧已消除全部可机器核验的驳回风险；剩余 3 项（隐私指引后台配置 / 类目资质 / 备案主体）为 MP 后台人工动作，需在提交微信审核前完成。
